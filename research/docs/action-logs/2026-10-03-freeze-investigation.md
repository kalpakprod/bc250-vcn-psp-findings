# Расследование зависания после включения 40CU

Plane: BC250-66, work item `f1f20e40-22c5-4af9-add5-f7406e525ed0`.

Запрос владельца: после запуска игры произошёл сбой/перезапуск, Home не реагирует. Позднее уточнено: консоль периодически полностью зависает с потерей ping; требуется расследовать и наладить запись причины.

## Подтверждённые данные

- Адрес `127.0.0.1`, пользователь steammachine. Начальные ping DOWN и SSH No route to host были наблюдением недоступности во время заявленного владельцем зависания, а не доказательством выключенной платы.
- Свежий доступ 2026-10-03 14:42:41 +05:00: ядро `7.2.8-1.2-cachyos-bore-bc250`, BIOS P3.00 12/09/2021, текущий boot id `a6e939e7-12fb-425b-b40f-10f3951570e3`, загрузка 14:40:21.
- Предыдущая загрузка `772cc50f954b4e15a6cfaf728db5b241`: 14:32:05–14:34:38. Журнал обрывается после запуска ACBlackFlag.exe, AppID 3751950, без штатного shutdown. Это согласуется с полным зависанием, но стек зависания не сохранился.
- Режим модуля 3; четыре shader array включены; ядро пишет `active_cu_number 40`.
- За время инцидента coredumps не найдены. В извлечённом журнале предыдущего ядра не найден диагноз GPU ring timeout, GPU reset, OOM или watchdog lockup. Начальные ошибки HPD/IRQ существуют, но относятся к инициализации, а не моменту зависания.
- В текущей загрузке NMI watchdog включён, `watchdog_thresh=10`, soft/hardlockup panic=1, panic timeout=10. Аппаратный SP5100 watchdog0 active, timeout=30; systemd RuntimeWatchdogUSec=30s. Второй watchdog не добавлялся.
- Текущая настройка: CPU3900/scale-34; GPU fixed2200/request1025mV по журналу governor. Наблюдавшиеся текущие температуры около68–73°C не доказывают температуры перед предыдущим зависанием.
- Steam controller_ui.txt: `Guide button sent to JS` в14:42:29 и14:43:56; смена фокуса на ClientUI769 и возврат к игре. Кнопка доходила до Steam. Причина отсутствия видимого меню ещё не определена.
- Steam также пишет ошибки сохранения shader cache и смешивание Proton-версий в compatdata/0. Эти сообщения сами по себе не объясняют полное зависание ОС.

## Исправление записи при зависании

Существующий `bc250-netconsole.service` failed: скрипт отправлял на устаревший192.168.1.151. Изменён только TARGET_IP на192.168.1.228; исходник сохранён на консоли в `/home/OWNER/.cache/bc250-freeze-investigation-20261003/bc250-netconsole.sh`. Сервис включён и запущен, configfs enabled=1, remote_ip192.168.1.228.

На этом компьютере добавлен `scripts/bc250_netconsole_receiver.py`, запускаемый `~/.config/systemd/user/bc250-netconsole-receiver.service`. Приём только с192.168.1.245, UDP6666, ограничение40MiB через ротацию. Лог: `evidence/runtime/20261003-freeze-netconsole/kernel.log`. Сервис active. Местный ufw блокировал приём; применено узкое правило от192.168.1.245 к192.168.1.228:6666/udp через системное окно pkexec. В14:50:40 сквозная проверка PASS: реальная запись `BC250-FREEZE-CAPTURE-VERIFIED` из /dev/kmsg консоли получена в файле на этом компьютере. Туда также приходят существующие BC250-METRICS.

30-секундное чтение только BTN_MODE с event11/event18 не поймало новых нажатий. Это не опровергает работу кнопки: нажатие в данном окне владельцем не подтверждено. Старые Guide button sent to JS остаются подтверждённым свидетельством.

Перезагрузок, остановки игры, смены CU/разгона во время расследования не выполнялось. Снимки предыдущих журналов сохранены в `~/.cache/bc250-freeze-investigation-20261003/`.

Откат: на консоли восстановить сохранённый скрипт и прежнее disabled состояние netconsole; на этом компьютере отключить receiver. Новое правило ufw, если применено, удаляется той же точной спецификацией с `ufw delete`.

Причина полного зависания пока не установлена. Следующее необходимое доказательство: off-box kernel trace при очередном сбое или контролируемое сравнение одной настройки после согласования условий. Если полностью останавливаются CPU/шина до сообщения ядра, netconsole не создаст отсутствующий стек; сохранится последняя доставленная запись. Приём требует включённого этого компьютера с адресом192.168.1.228.
