## Parser results (scripts/firmware_audit.py, read-only, reports in /tmp)
- Both vendor images: 16 MiB, PSP @0x8E0000 with 18 entries, Fletcher32 PASS,
  4 FVs, 245 extracted executables each, APCB @0xAB1000 size 0x488 with
  checksum PASS and stock DFG 0x001FFF00/0x001FFF00, AGESA V9 string.
- PSP types: 1,8,9,18,19,48,49,50,51,52,68,79,80,2,4,12,40,81. No 0x24/0x45
  (SEC_GASKET/TOS policy carriers) in either image. t28 (type 40) body
  `e5970657...` matches the corpus-C0A t28 already reconciled 2026-09-14.
- ARI drivers throughout (AmdCcxVhAri*, AmdFabricAri*, AmdNbio*ARI*,
  AmdSocBl5Ari*); one Cardinal module (`CardinalSystemHubSmmInit`).
- fTPM stack PRESENT in donor: AmdPspFtpmDxe + AmdPspFtpmPei (both images).
  BC250 dump/2.bin (234 modules) has no Ftpm/Tpm modules.
- GOP/VBIOS: NONE by module name in C08, C0A, or dump/2.bin; ATOMBIOS string
  count = 0 in all three images. Both have GraphicsConsole. Video-init path
  is a symmetric unknown, not a donor differentiator.

## Verdict (static-analysis, not hardware proof)
- Same SILICON family (Ariel): supported by ARI driver names in both images,
  identical PSP/FV/APCB layout, byte-identical SMU helpers and PCD GUID from
  the 09-14 audit, identical GfxPEIM entry skeleton, and press/manual sources.
  Single-source press claims (Tom's/wccftech) corroborate but do not prove.
- DIFFERENT board: Cardinal (A77E FCH, dGPU-only video, no 0x24/0x45 policy,
  smaller APCB, possible 8/16 GB SKU splits) vs BC250 card. A donor-as-base
  cross-flash is plausible but high-risk; memory training, FCH/GPIO/PCIe
  expectations, and missing GPU-policy carriers are the risk list.
- New leads for R2-R5: donor fTPM stack (TPM route), C08 as an older/fallback
  stack, Setup/AMITSE delta as the OC-menu surface to compare next.
