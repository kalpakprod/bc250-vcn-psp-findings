## Post-UMA NBIO transfer trace

Root decodes C0A GfxARIPei RVAs0x4D6..0x6F5 and helper ranges0x862..0x950,
0x13D2..0x1435 with TEdelta0x1A0. Preserve exact listing separately next.
Helpers:0x862 reads indirect PCI index/data (handles unaligned addresses);
0x8EC writes via0x1403;0x91A performs read/AND/OR/write via those helpers.

isolation semantics unproven. Absence of a previously guessed value in the
source registers would not alone exclude this copy path.

This donor path provides concrete destinations to compare in BC250, not
authority to replay donor memory-map values on a different board.

## Compact Gfx PEIM entry audit

Root used pypcode IA32 on the already hashed C0A Gfx PEIM with explicit
TE mapping: delta=0x1A0, entry RVA0x240=file0xA0. Existing disasm_x86_te.py
starts at section headers and emits zero-based shifted addresses, so it was
not used as an entrypoint-semantic oracle. Decoder output addresses here are RVAs.

Entry0x240 calls0xB60 then tail-jumps to0x24E. Observed flow locates a PPI,
walks descriptors, invokes hook0xB000000C and walks HOB records. Referenced
strings resolve exactly with file=VA-imagebase-delta and identify
AMD_MEMORY_INFO_HOB, NumberOfDescriptor, Base, Size, Attribute and fallback
'Hardcoding UMA information'. Attribute2 records drive UMA base/size calculations;
an exact2GiB size is adjusted to0x7F000000; absent-HOB fallback uses encoded
values0x100/0xD0/0xDF. Function pointer call after token0x4B can zero the
selected range, but token semantics are unresolved.

This establishes memory/UMA initialization as the first concrete path in the
compact donor module, not a proven VCN-unlock switch. Next compare the matching
BC250 entry path and subsequent NBIO writes with these named HOB inputs.
No firmware/board changes. No hardware semantic claim from string names alone.
