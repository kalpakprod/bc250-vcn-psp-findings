# CLV: реальная ветка Fix Voltage и граница SoC

## Выполненный следующий шаг

Взяты неизменённые ветки ISL69247 VCORE RVA30A и GFX RVA3A8. На вход подан явно синтетический Setup/frame с EBX0 и ESI900, как в предшествующем коде. Весь PEIM и его обнаружение оборудования не исполнялись. После выбора значения выполняется оригинальный helper6ED. Только helper565 заменён на trace, а733 останавливает выполнение до ожидания/чтения оборудования. Firmware и плата не изменены.

Результат для обоих label-путей:

| Случай                | Fix Voltage | Синтетическое слово | Слово в первой выходной команде21 |
| --------------------- | ----------: | ------------------: | --------------------------------: |
| BASELINE              |           0 |              0x0123 |                      0x0384 (900) |
| MODIFIED              |           1 |              0x0123 |                            0x0123 |
| Changed word          |           1 |              0x0456 |                            0x0456 |
| Disabled changed word |           0 |              0x0456 |                      0x0384 (900) |
| RESTORED input        |           0 |              0x0123 |                      0x0384 (900) |

Все10 процессов exit0, stderr пуст. Каждая команда имеет последовательность65:C0,66:21,70:low,71:high,63:03,60:C0. Каждый извлечённый модуль совпадает с исходным вне двух объявленных5-byte jump instrumentation sites. Сам исходный модуль сверяется с полным SHA256 и напрямую с ROM0xED2C74. ROM hash неизменён.

Это доказывает выбор слова реальной BIOS-веткой: при выключенном флаге пользовательское слово игнорируется и выбирается900. При включённом слово поступает в первую staged-команду. Числа0123/0456 синтетические, не рекомендации напряжения. Графический и процессорный paths проверены отдельно, но выбор физического bank/устройства до входа в ветку не исполнялся.

## Почему это не выдаётся как SoC setter

В открытом исходном GenCAD PUA1 маркирован ISL69247, его pins36/39 подключены к CORE_VSEN+/GFX_VSEN+. SoC feedback идёт к отдельному PUS1 pin4, SOC_FB, RT8237E. Полные pin/net-списки трёх контроллеров сохранены в controller-nets.json. Это дополнительные данные о различии путей, а не доказательство физической ревизии платы или невозможности любого косвенного управления SoC.

Практическое решение: VCORE Fix Voltage и GFX Fix Voltage не предлагать как первый SoC-шаг. Их значимость в собственных label-путях теперь подтверждена исполнением условного выбора, не только статическим чтением.

## Исправленный Memory P-state

Проверен token123C по сохранённым decoded-инструкциям233 x86 UEFI executable identities.20 совпадений:7 сериализаторов записывают значение Setup+36D,13 относятся к адресам/смещениям. Все затронутые окна сверены с байтами hash-pinned модулей. Прямой literal-requester в этом охвате не обнаружен. Косвенный доступ, таблицы, ARM ABL и SMU не исключены. Поэтому ещё один такой scan не является следующим полезным шагом.

## Следующее решение

Для BIOS-only SoC нужен другой доказанный аппаратный путь, не переименование VCORE. Текущая ветка ISL69247 закрывает вопрос о выборе слова, но не SoC. Продолжить независимый clock-path: точный ABL1 memory policy95FC и его upstream inputs. Переиспользовать существующие caller/provider отчёты и проверять только первый реально незакрытый переход. Цель1:1:1, начальный SoC<=1.15В и снижение задержки остаётся незавершённой.
