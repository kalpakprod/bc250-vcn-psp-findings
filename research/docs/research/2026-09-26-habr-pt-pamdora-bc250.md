## Суть

TOCTOU-атака на SPI-чтение модуля BL_PUBLIC_KEY в PSP boot chain.
PSP читает каждый модуль дважды (верификация, затем загрузка).
Raspberry Pi Pico 2 (PIO, 600-700 МГц) переключает CE между двумя SPI-флешками:

- Первое чтение: патченный BL_PUBLIC_KEY (свои RSA-2048 ключи)
- Второе чтение: оригинальный BL_PUBLIC_KEY

Результат: PSP принимает подменённые ключи, можно переподписать
TRUSTED_OS и DRIVER_ENTRIES (оба используют ключ 5A35).

## Специфика BC-250 / 4700s

- SPI чтение в Single-IO режиме, команда 03, по 4 байта
- Каждый модуль читается ДВАЖДЫ
- На десктопном Ryzen 5600: Quad режим, блоки 64 байта, одно чтение → TOCTOU НЕ работает
- Уязвимость специфична для BC-250 и AMD 4700s Kit

## Подпись модулей PSP

- RSA-PSS, SHA-256, salt_length=32
- Код подписи: PSPTool/psptool/crypto.py
- Помимо подписи, SHA-256 хеш в заголовке модуля тоже нужно пересчитать
- ABL модули подписываются В СЖАТОМ виде (PSPTool по умолчанию разжимает перед проверкой — баг)

## Вычитка IPL (off-chip bootloader, ~40 КБ, зашифрован)

Trusted OS при старте копирует себя в 0x0, перезатирая IPL.
Но на этапе ABL0 IPL ещё в RAM.
Метод: модифицировать entry point Trusted OS на 0x5C00, там код читает
IPL через обращения к SPI-адресам (0x27000000 + 0xC00000).
Данные видны на логическом анализаторе как адреса чтения флешки.
16 КБ за раз (watchdog), три прохода.

## Дебаг-канал через SPI

PIO модуль spi_debug ловит паттерн "03 Dx" в SPI-командах,
сохраняет следующие 16 бит адреса. Диапазон 0xDxxxxx.
Вывод по USB с Pico — быстрее чем DSLogic.

## Карта адресного пространства PSP (ARM, MMU off)

Доступные диапазоны получены брутфорсом через Data Abort handler.
check_address_access() возвращает 1 (OK) или 2 (abort).

## SysHub mapping (из IPL)

Три типа маппинга x86 адресного пространства в PSP:

- map_dram: flags 0xC0800000 — основная RAM
- map_fch: flags 0xC0000000 — I/O порты + MMIO
- map_fram: flags 0xC0808000 — Secure DRAM

Базовые регистры SysHub:

- 0x3230000 — slot register
- 0x32301F0 — mask
- 0x323026C — flags
- 0x3230308 — signature (0x3333)

SysHub brute-force результаты:

```
DRAM: 0000'00000000..0000'80000000 (x86 RAM low)
      0001'00000000..0004'7F300000 (x86 RAM high)
      FFFD'F7000000..FFFD'F7100000 (test RAM)
FCH:  0000'00000000..0000'10000000 (I/O ports)
      0000'FF000000..0001'00000000 (BIOS mapped)
      00FD'F9000000..00FD'F9100000 (0x7777 ??)
```

## Системные вызовы IPL

- SVC 0xF2 = запись аппаратного регистра (только адреса 0x3*)
- SVC 0xF3 = чтение аппаратного регистра (только адреса 0x3*)
- SVC 2 = чтение модуля (ABL1 и др.)

## Повышение привилегий (privilege escalation)

Через CCP DMA перезаписывается SVC-вектор в IPL:

1. Подготовить дескриптор DMA в 0x73000
2. Записать указатель на свою функцию по смещению 0x3C
3. Команда 0x500011, размер 4, source 0x7303C/0x020000, dest 0x28/0x020000
4. CCP регистры: HEAD=0x3002008, TAIL=0x3002004, CTRL=0x3002000 (значение 0x17)
5. После этого SVC 0 прыгает в свой код в supervisor mode

## Дамп PSP Boot ROM (0xFFFF0000)

Адрес блокируется после старта IPL. Решение:

1. Настроить CCP DMA chain: копирование 0xFFFF0000 (PSP, 0x10000 байт) в RAM
2. Добавить delay-операции (копирование RAM→RAM, чтение SPI)
3. Записать в 0x3200090 = 1 → CPU reset
4. После ребута DMA срабатывает до блокировки ROM
5. Первый запуск — мусор, после нажатия reset — валидный ROM

ROM BC-250 = ROM AMD 4700s (полное совпадение).

## Применимость к нашему проекту

Для TOCTOU нужен Raspberry Pi Pico 2 + две SPI-флешки + разведённая плата.
У нас есть только CH347 (SPI программатор). CH347 не может делать TOCTOU.

Однако статья даёт:

- Точные адреса CCP, SysHub, SVC — применимы при получении code execution
- Метод подписи модулей PSP (RSA-PSS SHA256 salt32)
- Факт: ABL подписываются в сжатом виде
- Карту адресного пространства PSP
- Метод дампа ROM через CCP DMA + CPU reset
