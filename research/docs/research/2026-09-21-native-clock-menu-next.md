# Exact-CLV native clock-control menu paths

## Conclusion

The pinned plain CLV 5.00 donor declares five logical clock-control groups as direct `AmdSetup` HII questions. The DF override group is two separate questions (`DF Clock Override Control` and its numeric value). All six questions are writable VarStore-bound IFR questions, `RESET_REQUIRED`, not read-only, and have no enclosing `SUPPRESS_IF`, `GRAY_OUT_IF`, or `DISABLE_IF` scope in the exact `CbsSetupDxe` package. Only `FCLK_DPM` carries the IFR `CALLBACK` bit. Thus none of these fields is **callback-only** at the question/storage-definition level.

This is not proof that all five groups are visible in the live BIOS. UclkDiv1M0 and Memory P-state have an unconditional package-local `REF` chain from form `0x7000` (AMD CBS). Memory Clock Speed's own form chain starts at `0x7007` (UMC Common Options), which has no incoming `REF` in this package. FCLK_DPM and DF Override are children of `0x7009` (SMU Debug Options), which likewise has no incoming `REF` in this package. The HII forms exist and their local references are unconditional, but the missing package-local entry to forms `0x7007` and `0x7009` leaves their full menu reachability unresolved; it does not prove they are inaccessible. No live Setup browser or AMITSE external registration was inspected.

## Direct questions versus callback-only behavior

- Each listed question has VarStore ID `0x5000` (`AmdSetup`) plus its own offset, and each has the read-only flag clear. The question definitions are `ONE_OF` for the enumerated fields and `NUMERIC` for DF value, rather than callback-only `ACTION` questions.
- Only FCLK_DPM has flags `0x14`, including `CALLBACK`; the other fields have `0x10`. This marks an additional callback path for FCLK_DPM, not a replacement for its VarStore binding. The callback itself was not invoked.
- Exact module bytes also show the `CbsSetupDxe` RouteConfig path through `ConfigToBlock` and an indirect call at module RVA `0x919` (`FF 50 58`) through the EFI Runtime Services `SetVariable` slot. The form data is therefore wired to a normal VarStore/RouteConfig persistence path in static code. Live browser execution, variable persistence, reset and readback were not tested.
- `RESET_REQUIRED` is metadata, not immediate clock application. The DF help text (`FCLK > UCLK` and Memory P-state disabled) is UI guidance, not proof of training behavior or physical clocks.
