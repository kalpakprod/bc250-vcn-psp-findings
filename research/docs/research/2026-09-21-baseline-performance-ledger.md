## Conclusion

There is **no current USER-board performance baseline** in the inspected project. The newest numeric performance primary located is a user-supplied AIDA64 screenshot from 2026-09-05. It shows `131.4 ns`, read `77619 MB/s`, write `112.05 GB/s`, and copy `118.53 GB/s`, but it is **not** a valid stock-vs-candidate result: it is contemporaneous with the operator's report of a manual VRM feedback adjustment, self-reported SoC around `1.2 V`, and requested DF `1800`; its exact active BIOS image, stored NVRAM, memory clocks, divider state, workload/repetition, and voltage measurement are not established. The reported voltage is outside the current operator limit; this is not a reproducible profile.

Earlier AIDA screenshots show `141.7 ns` / `66611 MB/s` read and, in a separate image, `141.3 ns` latency with throughput fields blank. The former occurred in a chat period where SYNC profiles 01/03 were reported to boot without the expected latency improvement. Neither is proven to be an unchanged-stock control, and neither is paired to the later image under controlled conditions. The apparent difference between screenshots must not be advertised as an improvement percentage or causal effect.

The project's current static donor (`BC250_5.00_clv.bin`) stores a memory-clock field whose exact CLV HII label is `1800MHz`; that is a request/menu identity, not a current-board readback or measured physical MCLK. Current board BIOS/NVRAM state, physical MCLK/UCLK/FCLK, SoC voltage, latency A/B, and FPS remain unverified/unrun. The 2026-09-15 gaming note records GPU busy at 100% but no FPS or frame-time value.

## Reconciliation: current known state versus old trials

1. **Current target state (2026-09-21):** no fresh target-board BIOS hash, NVRAM/Setup readback, POST/training capture, benchmark, FPS record, physical clock readback, or voltage measurement is present in the reviewed OC completion record. The `1800MHz` label is a pinned CLV donor request only. Therefore there is no current numeric baseline to compare against.
2. **Earliest screenshot evidence:** AIDA64 photo 7 is the only saved image in the older profile-boot episode with filled read/write/copy/latency boxes. AIDA64 photo 12 is a separate latency-only display. Their approximately similar latency values do not make a repeated-trial set: exact configuration and repeat protocol are missing.
3. **`131.4 ns` source:** the number is legible on photo 16, not a parsed benchmark log. The screenshot visibly labels the board `ASRock AMD BC-250` and BIOS `P5.00`; nearby participant messages report a physical feedback adjustment and SoC around `1.2 V` before/with DF `1800`. It does not show physical memory clocks, a divider, voltage instrument, training result or a controlled A/B. It must not be recast as evidence that BIOS SoC 1.15 V, 1:1:1, or any specific clock caused the value.
4. **BIOS identity:** all three AIDA screenshots visible in this ledger print BIOS version `P5.00`; none contains a BIOS-image hash or NVRAM dump. `P5.00` text alone does not tie the photographed boot to a particular SYNC attachment or to the present board state. The archived SYNC variants have been structurally compared to pinned CLV, but archive identity does not prove what was flashed when each photo was taken.
5. **Clock identity:** driver metrics and stored values are not independent physical measurements. Project memory records that exported FCLK/MCLK fields alias the same `MemclkFrequency` source; SMU `QueryDfPstate` returns a state/count, not MHz. The exact-board independent MCLK/UCLK/FCLK counter/divider path remains unvalidated. Thus screenshots and `DF Clock 1800` text cannot prove synchronization.
6. **Performance and voltage confounders:** no common binary/workload, CPU affinity, OS/kernel/driver, timing/NVRAM state, ambient/temperature, cooling, run count, or raw trial series is attached to the early/later screenshots. For photo 16 the reported manual feedback change and self-reported SoC `>1.2 V` are material confounders and exceed the present `1.15 V` operator constraint; that setting/result cannot be used as a recipe or a safe operating point.
7. **FPS:** the 2026-09-15 gaming evidence is usage/utilization context only. It contains no FPS/frame-time/1% low samples. No saved A/B gaming result is found in the current record.
