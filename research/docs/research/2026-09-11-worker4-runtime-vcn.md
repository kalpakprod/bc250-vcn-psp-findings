# BC250 Worker-4 Runtime VCN Unlock Design (Without Flash/SPI)

## H — Hypothesis

1. **SMU/Mailbox Path**: The SMU mailbox on Queue-3 (command address `0x03B10A20`, response `0x03B10A80`, argument `0x03B10A88`) combined with Queue-2 (`0x03B10528`) can program register and gasket states at runtime if the security lock (`0x7B3C`) is bypassed, but stock SMU 11.8 / PMFW 88.6.0 does not include a `PowerUpVcn` message.
2. **PSP/C2P Path**: TOS supervisor mailbox commands (`0x100B` token retrieval, `0x100C` blob load, `0x1033` application) can register policy and gasket blobs in RAM (`@0xE4E538`) without SPI flash modification, but verification of modified `$PS1` blobs by PSP remains cryptographically restricted unless a valid token or signing transform is satisfied.
3. **Driver/IPDS Path**: The Linux `amdgpu` driver explicitly skips IP version `2,0,3` (`cyan_skillfish2`) in `amdgpu_discovery_set_mm_ip_blocks()`, meaning even with hardware unclamp, the host driver ignores the VCN IP block unless overridden via module parameters, custom IPDS discovery override tables, or patched driver logic.
4. **MMIO Power & Gating Path**: VCN registers read `0xFFFFFFFF` because the Data Fabric (DF) firewall / SEC_GASKET clamps aperture access. Unclamping requires either boot-time signed gasket or privileged SMN writes (`0x0115A870` / Q3 `0x98`) which lock on cold reboot.

### Proven on Stock Board Today (`lspci -nn`, `/sys/kernel/debug/dri`, `dmesg amdgpu`)

1. **PCI Discovery (`lspci -nn`)**: GPU PCI device `1002:13fe` (AMD Cyan Skillfish graphics) is active and bound to `amdgpu`.
2. **IP Discovery Table (`/sys/kernel/debug/dri/...` or SPI offset `0x981A00`)**: IP discovery descriptor contains 38 IP records for 1 die; VCN record is present (`HWID 12`, version `2.0.3`, harvest `0`, MMIO bases `0x7800`, `0x7E00`, `0x02403000`).
3. **Driver Logs (`dmesg | grep amdgpu`)**: `amdgpu` loads, initializes display and compute blocks, but emits no VCN block initialization or `vcn_v2_0` messages because `IP_VERSION(2,0,3)` is bypassed.
4. **Direct MMIO Readback**: Reading VCN MMIO registers (e.g. `0x024078CA` / `mmUVD_VERSION`) on stock Linux yields `0xFFFFFFFF` (Data Fabric firewall clamping).

1. **SMN Gasket Writes**: Historical logs (`archives/imported/firmware-campaign/legacy-tmp-bc250-campaign/`) show 56 Bank-12 writes accepted via SMU Queue-3 message `0x98`, but VCN MMIO remained `0xFFFFFFFF` without domain power-gating and clock programming.
2. **TOS Mailbox Commands**: Architectural notes (`archives/imported/historical-bios-repo/legacy-bc250-bios/docs/10-runtime-unlock-recipe.md`) infer C2P/SOS mailbox command maps (`0x100B`, `0x100C`, `0x1033`), but executing them requires bypassing per-boot cryptographic tokens generated by the closed PSP.

## Q — Inventory of Stock-OS Runtime Paths (No SPI Flash Touch)

### 1. SMU Mailbox (MP1 / Queue 2 & Queue 3)

- **Exact Kernel Interface**: PCI configuration space indirect window at offset `0xB8` (index) and `0xBC` (data) via `/sys/bus/pci/devices/0000:00:00.0/config` (`O_RDWR` required; note: imported `bc250_smu` library performs writes and is not pure read-only).
- **Register / Mailbox IDs**:
  - Queue 2 (safe status/feature): CMD `0x03B10528`, RSP `0x03B10564`, ARG `0x03B10998`.
  - Queue 3 (privileged/OC/smn): CMD `0x03B10A20`, RSP `0x03B10A80`, ARG `0x03B10A88`.
  - SMN Gasket Command: `0x98` (smn write proxy).
- **Safe Timeout**: 100 ms poll interval on response register (`RSP != 0`).
- **Cleanup**: Restore register state; cold reboot if SMU locks or times out (`0xFE`, `0xFF`).
- **Expected Readback**: Response `0x01` (OK) for valid commands; `0xFF` or `0xFD` if locked/rejected.
- **One-Variable Signal**: Successful response `0x01` and non-zero register readback after SMN proxy write.

### 2. PSP Mailbox / C2P (TOS Supervisor)

- **Exact Kernel Interface**: Shared memory communication buffer / ACPI C2P message registers (or UEFI runtime service/driver interface).
- **Register / Mailbox IDs**: TOS dispatcher at `0xBA98` in TOS container (`0x984F00`); command codes `0x100B` (token), `0x100C` (load blob), `0x1033` (apply policy).
- **Safe Timeout**: 500 ms per mailbox transaction.
- **Cleanup**: Release allocated shared memory descriptors via service call `0x63`.
- **Expected Readback**: Status code `0x0` on success; error code `0xFFFF300F` on parameter/size mismatch.
- **One-Variable Signal**: Return handle (slot index + `0x10`) from command `0x100C`.

### 3. MMIO Power-Gating & Clock (Data Fabric / NBIF / SMU Power Domains)

- **Exact Kernel Interface**: Direct MMIO / SMN register access via kernel driver or debugfs.
- **Register / Mailbox IDs**: Power domain 6 enable (`FUN_00023b14(6,1)`), clock slots `0x16`/`0x17`/`0x18` (`FUN_00023744`), VCN aperture base `0x02403000`, UVD version `0x78CA`.
- **Safe Timeout**: Immediate MMIO read/write timeout (50 ms).
- **Cleanup**: None required for read-only checks; revert power domain state if written.
- **Expected Readback**: Non-`0xFFFFFFFF` value from `mmUVD_VERSION` (`0x024078CA`).
- **One-Variable Signal**: Transition of VCN version register from `0xFFFFFFFF` to `0x02000300`.

### 4. VCN Firmware Load Order & Driver IPDS Overrides

- **Exact Kernel Interface**: Linux kernel module parameters (`amdgpu`), device tree / IP discovery table overrides, `amdgpu_discovery.c`.
- **Register / Mailbox IDs**: `IP_VERSION(2, 0, 3)` check in `amdgpu_discovery_set_mm_ip_blocks()`.
- **Safe Timeout**: Standard module load timeout (5 seconds).
- **Cleanup**: `rmmod amdgpu`.
- **Expected Readback**: `dmesg` listing `vcn_v2_0` IP block initialization.
- **One-Variable Signal**: Presence of `vcn_v2_0` in kernel log and `/sys/kernel/debug/dri/0/amdgpu_pm_info`.

### 5. amdgpu Module Params / PCI Quirks / IPDS Overrides

- **Exact Kernel Interface**: `/sys/module/amdgpu/parameters/` or module load options (`amdgpu.discovery=1`, custom quirks).
- **Register / Mailbox IDs**: PCI ID `1002:13fe`.
- **Safe Timeout**: N/A (load time).
- **Cleanup**: Unload and reload module with default parameters.
- **Expected Readback**: Driver parameter reflection in `/sys/module/amdgpu/parameters/`.
- **One-Variable Signal**: Successful module initialization without hardware fault.

### 6. SMU Debugfs & Telemetry

- **Exact Kernel Interface**: `/sys/kernel/debug/dri/0/` (or matching card index).
- **Register / Mailbox IDs**: `amdgpu_pm_info`, `amdgpu_regs`.
- **Safe Timeout**: 100 ms file read timeout.
- **Cleanup**: None (read-only).
- **Expected Readback**: GPU power, clock, and IP block status.
- **One-Variable Signal**: VCN power state reporting `ON` instead of `OFF`/`N/A`.

## V — Ranked 3 Cheapest Read-Only Probes (Next Stock/Linux Boot, No Firmware Change)

### Probe 1: Stock Driver IPDS & VCN MMIO Aperture Probe

- **Action**: Run read-only query of PCI devices, kernel logs, and VCN version register via stock sysfs/debug tools.
- **Exact Commands**:
  ```bash
  lspci -nn -d 1002:
  dmesg | grep -i amdgpu
  sudo cat /sys/kernel/debug/dri/0/amdgpu_pm_info
  sudo python3 -c 'import mmap, os; fd=os.open("/dev/mem", os.O_RDONLY); mm=mmap.mmap(fd, 0x10000, mmap.MAP_SHARED, mmap.PROT_READ, offset=0x02400000); print(hex(int.from_bytes(mm[0x78CA:0x78CE], "little")))'
  ```

- **Expected PASS Signal**: `lspci` shows `1002:13fe`; MMIO read returns `0xFFFFFFFF` (confirming dataframe clamp baseline).

- **Expected PASS Signal**: Module info lists parameters; source check confirms `IP_VERSION(2, 0, 3)` bypass in discovery table.

### Probe 3: Safe Read-Only SMU Queue Status Probe

- **Action**: Check SMU health and status registers via non-modifying read configuration if PCI config read is permitted.
- **Exact Commands**:

## R — Risks & Constraints

1. **Hardware State Persistence**: SMN writes and register changes made via host config space are volatile and reset on cold reboot; improper mailbox commands can wedge the SMU requiring a physical power cycle.
2. **Data Fabric Firewall**: Attempting to read VCN MMIO without clearing the DF firewall results in bus master aborts or `0xFFFFFFFF` readbacks.
3. **Security Gate**: Unauthenticated runtime blob injection into PSP/TOS is rejected by the supervisor signature verification unless valid RSA tokens or valid policy structures are presented.
4. **No-Flash Rule**: Adhering strictly to task design constraints: **NO execution, NO flashing, no repository writes except this report (`docs/research/2026-09-11-worker4-runtime-vcn.md`)**.
