# Diff v2000a APCB VCN tokens — результат

Задача: найти в v2000a (Renoir, ближайший рабочий родственник) VCN-токены,
которые через APCB доезжают до SMU/железа, и решить, можно ли включить VCN
BC250 правкой одного APCB.

Итог одним абзацем: APCB в корпусе v2000a у нас физически отсутствует
(локальные дампы — только PSP-область), но ответ это не меняет: конфиг-данные
BC250 уже говорят «VCN присутствует, harvest=0» — ровно как у v2000a.
Отключение VCN сделано не в APCB, а в подписанных носителях и SMU.
APCB-патч без подписи нечему включать.

## 1. v2000a APCB: не нашёл

Проверено в обеих локальных копиях v2000a
(`archives/imported/recon-evidence/legacy-tmp-bc250-recon/v2000a/`):

- `V2000A_M.fd`, 786 432 B, sha256 в `evidence/firmware-audit/20260923-v2000a-apcb-vcn-tokens/diff-result.json`
- `V2000A_S.fd`, 589 824 B

Скан полного содержимого обоих файлов:

- сигнатура `APCB` / `$APCB`: **0 совпадений** (ASCII и UTF-16LE `41 00 50 00 43 00 42 00`)
- ASCII `VCN`, `UVD`, `VCE`, `JPEG`, `Vcn`, `vcn`: **0 совпадений**
- `$PSP`/`2PSP`-каталоги присутствуют, `APOB` присутствует (M: 18, S: 10 совпадений `APOB`)

Вывод: это вырезанные PSP-области (recon-дампы по 576–768 КБ), а не полные
BIOS — APCB в них не попал. Где брать полный v2000a BIOS в корпусе — неизвестно,
в `docs/research/2026-09-17-c3-v2000a-8c-rung.md` перечислены только эти артефакты.

## 2. Чем v2000a реально доставляет VCN-конфиг: подписанный носитель + gasket

В том же каталоге лежит разбор подписанного носителя политики:

- `security_policy_RN_FP6_AM4_PspBl.sbin`, 11 952 B — из него извлечены
  `HwIpCfg_RN_A0.body` (1380 B) и банк записей `vcn_gasket_bank.txt`
- `HwIpCfg_RN_A0.parsed.json`: Hardware IP Config, сигнатура `0x28211407`,
  версия 1.1, таблица IP discovery v2, 41 IP-блоков
  - VCN: hw_id 12, instance 0, версия **2.2.0**, **harvest=0**,
    базы `0x00007800`, `0x00007e00`, `0x02403000`
- `vcn_gasket_bank.txt`: 56 записей типа `0x201`/`0x280` по MMIO `0x0900c2xx–0x0900cbxx`
  — это и есть gasket-записи, которые носитель льёт в SMU-область вокруг VCN

То есть у v2000a VCN-конфиг доезжает не через APCB, а через подписанный
PSP-носитель (политика + HwIpCfg + gasket-записи). Это тот же класс объектов,
что «carriers 0x24/0x45» у BC250 — переподписать их нельзя.

## 3. BC250: свой HwIpCfg уже описывает VCN как присутствующий

Файл `evidence/donor/retroweb-20260916/BC250_5.00_clv.bin`
(sha256 `ea578104…ca4cb8`, 16 777 216 B):

- HwIpCfg по сигнатуре `0x28211407` найден ровно один раз: **смещение 0x981a00**,
  лежит внутри PSP-записи типа `0x20` @ `0x981900`, размер записи `0x650`
  (смещение внутри записи: +0x100)
- Парсер `import/.../recon/parse_hw_ip_config.py` (тот же, которым получен
  v2000a-разбор): 38 IP-блоков, среди них
  **VCN: hw_id 12, instance 0, версия 2.0.3, harvest=0**,
  базы `0x00007800`, `0x00007e00`, `0x02403000` — те же адреса, что у v2000a
- sha256 первых 1380 байт блока: `bb6eddca78b571e1…` (полный в JSON)

Разница с v2000a только в версии IP (2.0.3 против 2.2.0) и числе IP-блоков
(38 против 41). Harvest-биты везде 0. Конфигурационный путь BC250
**не отключает** VCN — данные говорят «блок есть».

## 4. APCB BC250: VCN-токенов нет

APCB BC250: `BC250_5.00_clv.bin` @ `0xAB1000`, заголовок
`41 50 43 42 20 00 20 00 9c 0b 00 00 …` (магия `APCB`, размер `0x0B9C`).

- Скан групп по методике `scripts/donor_4700s_vcn_diff.py`
  (`UNKN/PSPG/DFG /MEMG/FCHG/CBSG`): DFG/MEMG/PSPG-групп **не найдено** —
  первым «совпадением» является ложное `UNKN` @ `0xab1020` (gid 2823, size 1),
  это не валидная группа
- Скан всей 16-МБ картинки на ASCII `VCN/UVD/VCE/JPEG`: **0 совпадений** —
  ни в APCB, ни где-либо ещё
- Предыдущий прогон того же скрипта
  (`evidence/firmware-audit/20260923-donor-4700s-vcn/diff-result.json`)
  тоже дал пустой `dfg_words: {}` — DFG-слов, отличающих 4700S от BC250,
  не нашлось и там

То есть даже если бы APCB-патч был нужен — в APCB BC250 нет ни одного
VCN/UVD/VCE-токена, который можно было бы «включить» или скопировать с донора.

## 5. Вердикт

**APCB-only патч не может включить VCN на BC250.**

Основание:

1. Единственный VCN-конфиг в BC250-образе (HwIpCfg @ 0x981a00) уже описывает
   VCN как присутствующий (`harvest=0`, те же базы, что у v2000a). Включать
   в данных нечего — данные уже «за» VCN.
2. Конфиг v2000a, который реально отличается (gasket-банк `0x0900c000`,
   политики), доставляется подписанным носителем
   (`security_policy_RN_FP6_AM4_PspBl.sbin` → `vcn_gasket_bank.txt`),
   а не APCB. У BC250 эквивалент — носители 0x24/0x45, переподписке не поддаётся.
3. В APCB BC250 нет ни одного VCN-релевантного токена (скан по сигнатурам
   групп и ASCII — ноль), копировать с донора нечего.

Неопределённость:

- Полный v2000a BIOS с настоящим APCB в корпусе отсутствует (п. 1), поэтому
  тезис «в APCB v2000a тоже нет VCN-токенов» — наблюдение по нашей копии,
  а не доказательство для любого v2000a BIOS.
- Анализ статический: то, что HwIpCfg лежит в подписанной PSP-записи типа
  `0x20`, и то, как загрузка её валидирует на железе, не проверялось.
- Если APCB-группы в BC250 закодированы иначе, чем ожидал парсер донорского
  скрипта (я нашёл только ложное `UNKN`), формат стоит разбирать заново —
  но это меняет лишь полноту пункта 4, не пункты 1–2.
