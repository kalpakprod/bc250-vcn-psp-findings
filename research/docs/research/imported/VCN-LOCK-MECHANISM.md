# BC-250 (Cyan Skillfish 13FE): механизм блокировки VCN и план разблокировки
Полный реверс-инжиниринг. Дата: 2026-09-03 (донор-диф закрыт 09-04; подпись/APCB —
09-05; APCB v2 формат + чексумма D1 решены 09-05 против OpenSIL/PT/ROG-Ally;
дизасм t01/t02/t28 + распаковка FVMAIN + потребитель DFG найден — текущая сессия).
Все офсеты проверены на реальных образцах; донорские значения — байт-точные из локального
гаскета Cezanne A3MSTX 370e (dir1 ≡ dir3).

## 1. Цепочка загрузки и где именно убит VCN

```
SPI NOR 16MB (W25Q128BV)
  └─ PSP L1 каталог @0x8E0000 ('$PSP', checksum 0x63FFFCC8, 19 записей по 16Б:
       {type u32, size u32, loc u64 = 0xFF000000+SPI} )
       0x01 PSP bootloader  0xA800  @0x8E0400
       0x02 PSP secure OS   0x14350 @0x8EAC00
       0x08 PMFW (SMU) A    0x40200 @0x8FF000   ← Xtensa SMU 88.6.0
       0x12 PMFW (SMU) B    0x40200 @0x93F700
       0x24 SEC GASKET      0x2E50  @0x982000   ← ГЛАВНЫЙ ЗАМОК (см. §2)
       0x13 DEBUG_UNLOCK    0x2000  (RSA-2048 токен; ключ AMD — НЕ подделать)
       0x45 TOS policy      0x6E0   @0x9CA400
       ... (19 записей всего; полный дамп: bc250_firmware/psp_dir.txt)
  └─ IP-discovery блоб @0x981A00 (0x44C, 38 IP, 1 die)
  └─ AtomBIOS 113-AMDRBN-003 (55296Б; живой дамп совпал md5 с 1002_13FE_vbios_dump.rom)
```

Каждый PSP-блоб: заголовок 0x200 = 16Б nonce + '$PS1' + u64 size + key-id 16Б @0x38
+ {тип, 01 01} @0x58 + u32 ВЕРСИЯ @0x60 + u32 total @0x6C.
Версии: гаскет = **B.51.0.16** (Robin), TOS = B.51.1.16, PMFW = 88.6.0 (0x00580600).

Гаскет применяется PSP на раннем буте (фаза DRIVER_ENTRIES, до AGESA DXE);
фабрик-регистры после записи **hardware-lock до холодного рестарта**.
Хостовые записи в рантайме дропаются (LockDFReg 0x1b; измерено: ctrl 0x02→0x00
читается как 0x02). DEBUG_UNLOCK (type 0x13) — единственный легальный
runtime-путь, требует RSA-2048 токен, подписанный ключом AMD (kid 6c5f…) —
закрыт. Вывод (подтверждён независимо прежней сессией, VCN-UNLOCK-CORRECT-CHAIN.md):
**устойчивый анлок = модификация подписанного SEC_GASKET в SPI ROM.**

## 2. Пять слоёв блокировки (что доказано)

**Слой 1 — железо/discovery: НЕ РЕЗАНО.**
Discovery-таблица (и в ROM @0x981A00, и в живом TMR-блобе 10240Б с платы):
запись VCN (hw_id UVD, v**2.0.3**, базы 0x7800/0x7E00/0x02403000 = побайтно
renoir UVD0_BASE), **harvest=0**; harvest-таблица ('HARV' @0x3C4) **пустая**.
PSP пересобирает TMR-блоб при буте — но VCN-запись сохраняет. Железо VCN есть.

**Слой 2 — ядро Linux: ПУСТОЙ CASE.**
`amdgpu_discovery_set_mm_ip_blocks()` (drivers/gpu/drm/amd/amdgpu/amdgpu_discovery.c):
```c
case IP_VERSION(2, 0, 0): case IP_VERSION(2, 0, 2): case IP_VERSION(2, 2, 0):
        amdgpu_device_ip_block_add(adev, &vcn_v2_0_ip_block); ...
case IP_VERSION(2, 0, 3):
        break;              /* ← VCN 2.0.3 (cyan_skillfish2) СОЗНАТЕЛЬНО ПРОПУЩЕН */
```
Отсюда: UVD/VCN/VCE 0.0.0 в amdgpu_firmware_info, отсутствие ip-блока в dmesg,
отсутствие файла cyan_skillfish2_vcn в linux-firmware (там только 8 CP+SDMA).
Фикс: кернел 1.92 `linux-cachyos-vcn-bc250` (установлен на плате, ни разу не
загружался) с `amdgpu.bc250_vcn_mode=1` — заполняет пустой case.

**Слой 3 — PSP SEC GASKET политика (главный замок), тип 0x24, B.51.0.16.**
Из ROM @0x982000 (0x2E50Б), структура решена полностью:
```
@0x140 группа[0] window 0x201 count 1230   (SMN-банки + DF окна + NBIO)
@0x27B8 группа[1] window 0x203 count 31    (0x0322 varA)
@0x28B8 группа[2] window 0x210 count 13    (VCN_SEG!)
@0x2928 группа[3] window 0x280 count 100   (recommit: DF окна + VCN-банк донора)
@0x2C50 группа[4] window 0x281 count 31    (0x0322 varB = TOS-зеркало)
Итого ровно 1405 записей = «Robin 1405 (5 groups)» из A1-реплея.
Запись = 8Б {addr u32, value u32}. 400/400 контрольных A1-пар легли в блоб
смежно (addr+4=value) — A1-реплей дословно воспроизводит этот блоб.
```

Кросс-таблица Robin ↔ Cezanne (донор), байт-точная (recon/robin3 vs
recon/cezanne_a3mstx_370e/dir1_sec_gasket_12.parsed.json). Robin1 ≡ Robin3 ≡
Robin5 — ВСЕ версии BIOS BC250 несут идентичную политику убийства:

**Слой 4 — питание домена-6 (SMU PMFW 88.6.0).**
Слоты тактирования 0x16/0x17/0x18 dom6: enable=0 (off), статус READY.
Секвенсор dom6 SMN 0x0006D1xx читается хостом, записи хоста игнорируются;
вписывает только SMU (fw-window msg 0x28/0x29; thunk msg 0x61 = собственный
teardown-код прошивки; кандидат: Q3 0x3C feature-bitmask — у renoir PowerUpVcn
гейтится именно так). Q3-таблица: 147 обработчиков (SRAM 0x746C).

**Слой 5 — прошивка VCN.**
Файла нет; донор = **renoir_vcn.bin** (VCN 2.x, 405952Б, есть на хосте с
cdn.kernel.org): карта регисторов VCN2 (467 рег.) побайтно сверена с ядром,
базы discovery идентичны renoir. (navi10 = VCN 1.0 — неверное поколение.)
Родной блоб — внутри шифрованного kernel.bin PS5 (ветка 4PDA, ≤3.21).

## 3. Рецепт кастомного BIOS (полный транплант донора)

База: BC250_3.00_CHIPSETMENU.ROM (16МБ; = аппаратному дампу W25Q128BV в
PSP/discovery-областях). Правки ТОЛЬКО в блобе type-0x24 @0x982000.

**Ступень A — минимальный анлок (3 правки, минимальный риск):**
1. группа 0x210: `0x03E810: 0x00000000 → 0x00000006` (12 биндинг-слов 0x03E814
   уже на месте, слово 2544c382 общее с донором — оставить как есть);
2. группы 0x201 И 0x280: `0x03A2011C: 0x87FF → 0x107FF`;
3. группа 0x201: `0x03A20124: 0x00000000 → 0x00010FFF`.

**Ступень B — VCN-банк SMN (апертура фаервола): уже собрана.**
`recon/bc250_sec_gasket_with_vcn_UNSIGNED_DO_NOT_FLASH.bin` (11792Б, +448Б):
прежняя сессия добавила ровно 56 записей банка HWID-12 (51 → 0x201, 5 → 0x280);
sha256 банка байт-в-байт = донорскому (verify.json). Но сборка НЕ трогала
ступень A (0x03E810=0 и DF-окна остались Robin!) — объединить A+B.

**Ступень C — полный донор-транплант (по мере необходимости, если A+B мало):**
4. банк-зеркало 0x03D2: добавить 0x03D2011C=0x107FF, 0x03D20120=0xFFFF0000,
   0x03D20124=0x10FFF, 0x03D20128=0xFFFF0000 (0x201+0x280) + 0x03A20128=0xFFFF0000;
5. IOHC-окна: 0x0322011C→0x10000 (0x203)/0x103FF (0x281), 0x03220124→0x10707
   (0x203)/0x107FF (0x281), 0x0322012C→0x101FF (0x203)/0x10BFF (0x281);
6. NBIO-мост: 0x09018934/38 → 0x13b10400/0x13b10bff + добавить серию
   0x090189A0…E4 донора;
7. fabric-блок 0x0001C760…0x0001C788 + 0x0001D080/0x0001D4FC по донору.

Затем: PSP-каталог не меняется (размер блоба растёт — пересчитать size/total в
заголовке и записи каталога; подпись-хвост 0x100 сохранить на новом конце —
см. §6). Прошивка
через afulnx/AfuEfi64 (community-тулчейн, инструкции «EFI update Bios Step.pdf»).
После снятия гаскета: бут кернела 1.92 с `amdgpu.bc250_vcn_mode=1` +
renoir_vcn.bin (+ при необходимости dom6 через 0x61/0x3C — если PMFW не
поднимет домен сам, как на платформах донора).

Порядок риска: A (3 регистра, обратимо в мыслимом пределе) → A+B → A+B+C.
Без программатора и полного бэкапа чипа НЕ прошивать.

## 4. Риски и неизвестные

- **Подпись PSP — см. §6**: формат решён (0x100 hdr + тело + 0x100 RSA-хвост),
  ключи лежат в ROM (t50/t51 $KDB), подписи детерминированы; офлайн-RSA-проверка
  не воспроизведена → схема нестандартна/AES-обёрнута; исполнение проверки =
  только аппаратный тест с программатором (дампер W25Q128BV у пользователя есть).
- **DEBUG_UNLOCK 0x13** — RSA-2048 токен с ключом AMD: путь закрыт окончательно.
- **Питание dom6**: после снятия гаскета домен может подняться сам (как у
  донора) или потребовать 0x61/0x3C — проверить по UVD_POWER_STATUS.
- **Van Gogh-нюанс**: у Van Gogh (рабочий VCN 3.0.2, гаскет B.51.0.37) записи
  0x3E810=6 НЕТ → регист не универсален; но для нашего транпланта важен донор
  того же семейства DF (Cezanne/renoir-deriv) — значения подтверждены.
- **Хвост блоба = подпись 0x100** (не «неизвестный хвост»): при росте тела
  (ступень B +448Б) пересчитать каталог (size) и сохранить место под 0x100 хвост.
- **DTR 0x03E814**: 12 слов Robin vs 1 слово донора — вероятно FIFO-регистр
  (каждая запись пушит слот). Слот 2544c382 общий; поведение лишних слов при
  enable=6 неизвестно — safest-вариант: оставить (они и сейчас пишутся).

## 5. Моды сообщества и аппаратный дамп (диф закрыт)

- ВСЕ моды (bc250-Steam / 8_cores_Steam / modded / «стоковый» 3.00.ROM) патчат
  ровно ОДИН непрерывный регион **0xAE0088..0xC27xxx (~1.3МБ) = UEFI**;
  PSP-регион (0x8E0000..0x9E0000) и APCB (0xAB1000..) не тронут НИ ОДНИМ модом.
- **Аппаратный дамп чипа W25Q128BV == CHIPSETMENU-базе байт-в-байт во всём
  PSP-регионе** (0 diff) → BC250_3.00_CHIPSETMENU.ROM верифицирован как
  флеш-база против реального кремния. Расхождения: UEFI (0xAE0088..0xC22C8B),
  живой NVRAM (0xED/0xEF), ранний блок 0x32A..0xA575.
- **Robin5.00 = ПОЛНОЕ обновление PSP+UEFI** (новый каталог, новые блобы),
  но гаскет байт-идентичен 3.00 (md5 5b2b90210e53, kill-значения те же) —
  убийство VCN пережило мажорный апдейт AMD. Robin1≡Robin3≡Robin5.
- Robin5 обновил и APCB: дата-токен 0x261121→0x060422 + блок 0xAB1440..0xAB1B64
  (токены ПОСЛЕ PSPG/DFG/MEMG; сами permission-группы не изменились).

## 6. Схема подписи $PS1 (решена структурно; исполнение — только тест на железе)

Формат блоба (исправлен — заголовок 0x100, НЕ 0x200):
```
0x000..0x100  $PS1-заголовок: nonce 16Б @0x00 | '$PS1' @0x10 | body_size u64
               @0x18 | 16Б нулей | флаг @0x30 (01) | key-id 16Б @0x38 |
               body_size u64 @0x50 | {формат,01 01} @0x58 | версия @0x60 |
               total u32 @0x6C
0x100..(0x100+size_signed)  тело (= size_signed из заголовка; у гаскета 11344)
хвост 0x100 (256Б)          ПОДПИСЬ (энтропия 7.0-7.3; у ВСЕХ политик-блобов)
```
- **Контейнеры ключей в ROM**: t50 BL_PUBLIC_KEY = '$KDB' с 8×RSA-2048
  {exp=65537, key-id 16Б, bits=2048, модулус 256Б @rec+0x50, запись 0x150Б};
  t51 TOS_KDB — ещё 3-4 ключа. **key-id КАЖДОГО блоба резолвится в ключ из
  t50/t51** (гаскет и TOS-политика → 96ea7cfe…; PMFW → 8b8df41e…; ABL →
  663ca522…; PSP-OS/DRIVER_ENTRIES → 5a3587b5…; HW_IP_CONFIG → 537b4c2e…;
  DEBUG_UNLOCK → 9f0d3830…; XHCI → 9ace85d9…; t4F → 39bfc192…).
- **Полный детерминизм**: гаскет байт-идентичен (nonce+подпись) во всех 4
  независимых образцах (3.00 / 5.00 / board-dump / hw-chip) → подпись не
  рандомизирована (PKCS-стиль, не PSS).
- **Офлайн-верификация НЕ воспроизведена**: 11 ключей × 5 трансформаций
  модулуса × 3 подписи × 2 endian × 15 спанов × 4 хеша = пусто → схема
  нестандартна (вероятно AES-обёртка подписи с fused-ключом по key-id, или
  нестандартный спан). PSP-бутлоадер (t01, 43КБ ARM) — валидатор; его разбор
  даст точный алгоритм.
- **Следствие для пути A**: любая правка тела гаскета ломает хвост-подпись.
  Если PSP проверяет (стандарт для PC-парт) — блоб отвергается. Soft-fuse
  гипотеза (майнер-парт без верификации) НЕ подтверждена и НЕ опровергнута —
  решается ТОЛЬКО аппаратным тестом: программатор + полный бэкап, прошить
  модифицированный гаскет, при кирпиче — откат программатором.

## 7. Путь B: APCB/DFG-гейт БЕЗ подписи (VULN-BC250-002; D1 ЗАКРЫТ 09-05)

### 7.1 Формат APCB v2 решён полностью (OpenSIL AGCL-R + PT Slowburn + ROG-Ally-тул)

BC250/4700S = **APCB v2** (header 0x20, version BCD 0x20; ECB2/BCPA-расширения v3 нет).
Источники: openSIL/AGCL-R `AgesaPkg/Addendum/Apcb/Inc/Genoa/ApcbV3Arch.h` (структуры
совпали байт-точно), Positive Technologies «Slowburn: Looking through AMD Platform
Configuration Blobs» (swarm.ptsecurity.com, 2026-04; CVE-2025-54502 в AmdApcbSmmV3),
95JakeHex/APCB_ROG_Ally `Man_edit_apcb_checksum_fix.py` (алгоритм чексуммы).

```
APCB_V2_HEADER (0x20Б): { 'APCB' | SizeOfHeader u16=0x20 | Version u16=0x20(BCD 2.0)
  | SizeOfApcb u32 | UniqueApcbInstance u32 @+0x0C | CheckSumByte u8 @+0x10 | rsvd }
APCB_GROUP_HEADER (16Б): { sig | GroupId u16 | SizeOfHeader u16=0x10 | Version u16
  | Reserved u16 | SizeOfGroup u32 }
  GroupId: PSPG=0x1701, CCXG=0x1702, DFG=0x1703 (Data Fabric Group!), MEMG=0x1704,
           GNBG=0x1705, FCHG=0x1706, CBSG=0x1707, OEMG=0x1708, TOKN=0x3000
APCB_TYPE_HEADER (16Б): { GroupId u16 | TypeId u16 | SizeOfType u16 (ВКЛ. заголовок!)
  | InstanceId u16 | rsvd1 u32 | rsvd2 u32 }
```
Наш DFG @0xAB10F4 = {'DFG ', 0x1703, hdr 0x10, ver 1, size 0x88} + **тип 5** (size 0x3C
= 16Б заголовок + 44Б данных = 11 строк) + **тип 6** (идентичен байт-в-байт). Публичные
Genoa-типы DFG (0x00D0 xGMI TxEq / 0x00CC CXL / 0x00DD PhyOverride) ≠ наши →
**типы 5/6 — майнер-кастом AMD** (access-control строки).

### 7.2 D1 закрыт: алгоритм чексуммы решён и верифицирован 12/12

**Поля перепутаны прежними чтениями** (и параллельным агентом): @+0x0C =
**UniqueApcbInstance** (сборочный штамп BIOS-версии, НЕ чексумма), настоящая
контрольная = **u8 @+0x10**:
```
CheckSumByte = (0x100 − Σ байт APCB [0 .. SizeOfApcb), пропуская сам +0x10) & 0xFF
```
Верифицировано на 12/12 сэмплах: BC250_3.00 (0x9C), dump_5.00 (0xD7), my_4.0_MODED
(0xC9), Robin5 ×2 (0xD8, size 0x488), оба аппаратных W25Q128BV (0xC9), 8core/Steam/
modded/3.00.ROM (0x9C), **4700S c0a (0x5E)**. UniqueApcbInstance-штампы:
3.00=0x220E, 4.00=0x25DE, 5.00=0x1C05, 4700S=0x24ED. Доказательство штампа:
dump_5.00 (тело 0xB64, 3.00-токены) и Robin5 (пересобранное тело 0x488) делят 0x1C05
при разных телах; my_4.0_MODED отличается от 3.00 ТОЛЬКО штампом+чексуммой при
байт-идентичном теле. Аппаратные дампы == my_4.0_MODED → на плате пользователя
флешнут 4.0-мод с нетронутым APCB-телом. **При патче DFG штамп НЕ трогаем**
(совместимость с UEFI-lifecycle), пересчитываем только u8@+0x10.

### 7.3 DFG: полный построчный декод (оба типа 5/6 идентичны)

```
master=01 (x86?), grant-строки:  sub 01..05 → perm 0x03   (базовая, без grant-битов)
                               sub 06    → perm 0x63      (биты 0,1,5,6)
                               sub 08    → perm 0x23      (биты 0,1,5)
wildcard-строки:  {00, ff, 1f, 00}  любой master × любой sub → базлайн 0x1f (БЕЗ битов 5/6)
                  {03, 80, 07, 07}   master 03 → sub 0x80 perm 07
                  {03, 00, 00, 00}   master 03 → sub 00 = deny
                  {10, ff, ff, ff}   master 0x10 (secure) → всё 0xff («match-all-secure»)
```
Строки sub=12 (VCN) НЕТ. Модель (сверка с параллельным агентом): его «VCN-подблок
присутствует без grant-бита» = по факту wildcard-базлайн 0x1f (VCN под ним, битов 5/6
нет = закрыт), но НЕ явная строка. У Cezanne-донора (VCN работает) DFG-групп НЕТ
вообще → default-политика = open; DFG в майнер-сборках существует, чтобы ЗАКРЫВАТЬ.

### 7.4 D2: соответствие sub ↔ железо (частично решено, суб-номер VCN открыт)

- Гаскет Robin программирует SMN-банки {00,01,02,03,04,05,06,07,08,09,0a,0b,22,30,a2}
  (биты 16-23 адресов 0x09XXxxxx); grants 06=0x63/08=0x23 коррелируют с банками 6/8,
  но банки 7,9,a,b программируются БЕЗ DFG-строк → sub-пространство ≠ SMN-банки 1:1.
- **VCN-банк гаскета = SMN 0x0900Cxxx (HWID 12)**: донор пишет 56 записей (8 MMIO-
  диапазонов 0x21800-0x218ff / 0x20300-0x206ff / 0x1f844-0x1f84f / …, policy_mode
  0x36, attributes 0x307, access_masks 0x00fffffb/0x00ffffff); **Robin не пишет туда
  НИЧЕГО** (0 записей). Апертурная программа VCN целиком внутри ПОДПИСАННОГО гаскета.
- Следствие (сходится с VULN-1: SMN-реплей принимался, x86 MMIO оставался 0xFFFFFFFF):
  **двухзамковая модель = DFG/dom6-разрешение + гаскет-апертура**. APCB-патч ОТКРЫВАЕТ
  dom6/DF-слой, но банк 0x0900Cxxx должен программировать гаскет (ступень B из §3).
  Полный анлок = APCB-строка + UNSIGNED-гаскет (или soft-fuse-тест пути A).
- Кандидаты патча DFG (совместимы со штампом):
  (i) 1 байт: wildcard-базлайн `00 ff 1f 00` → `00 ff 7f 00` (поднять базлайн, размеры не трогать)
  (ii) добавить `01 0c 63 00` в оба типа (sub=0x0C=HWID 12; Sizes +4/+4, SizeOfApcb +8)
  (iii) in-place: `01 01 03 00` → `01 0c 63 00` (закрывает sub 01 — рискованнее)
  После любой правки — пересчёт u8@+0x10 по §7.2. Инструмент: tools/apcb_cks_brute.py
  (содержит проверенную chksum-функцию) + простой скрипт пересчёта.

### 9.2 D3-подготовка (текущая сессия) — образы ГОТОВЫ

**Решённые форматы** (все верифицированы программно на дампе платы):
- **Чексумма PSP/BHD каталога** = `fletcher32([dir+0x08 .. dir+0x10+count*esz))`
  (PSP: 19 записей × 16Б, конец @+0x140; BHD: 4 записи × 24Б — с Destination! —
  конец @+0x70). AGESA-хедер называет это "32 bit CRC", фактически fletcher32.
  PSP @0x8E0000 = 0x63FFFCC8 ✓, BHD @0xAB0000 = 0xECE7B2E6 ✓. Поле @+0x0C —
  НЕ размер, а AdditionalInfo-битфилд (MaxSize/SpiBlockSize/BaseAddress/Mode).
- **$PS1-конверт гаскета** (ориг @0x982000, 0x2E50): u64 size @+0x14 и @+0x50
  (=0x2C50, тело), u32 total @+0x6C (=0x2E50); хвост 0x100 = подпись. Заголовок
  0x100 + тело (0x40-заголовок + группы {type u32, count u32, пары {addr,value}})
  + хвост 0x100.
- **Тело UNSIGNED** 0x2E10: группы 0x201(1281=1230+51 VCN)/0x203(31)/0x210(13)/

  0x2b74) 0x87FF→0x107FF, 0x03A20124 (grp 0x201, body+0x2604) 0→0x10FFF;

## 10. D3: инструкция аппаратного теста (только с программатором!)

**Передаваемый пакет v3 = `recon/d3/package/`** (README_RU.md — полная
инструкция тестеру; ниже — краткая выжимка для нас). Порядок прошивки:
**01 D3-C (механика) → 02 D3-B2 (главный) → 03 D3-A (контроль)**.

Порядок обязателен; все шаги на выключенной плате, SPI-программатор
(W25Q128BV = 16МБ, питание 3.3В, корпус SOIC8 — стандартная прищепка
SOIC8; резервный вариант WSON8 описан в README пакета).

0. **Снять полный дамп чипа (16МБ)** и сверить md5 с эталоном
   7607a34caeca1ffb95e1f7c52ca227d5. Совпал → шей пакет как есть;
   не совпал → СТОП, прислать дамп, пересоберём образы под его базу.
1. **D3-C (S-версия, подпись валидна)**: плата обязана завестись как
   сток — это доказывает механику (правка каталога + fletcher32 +
   перенос блоба на 0x9E0000). Не завелась → откат, разбор: PSP валидирует
   каталог строже (версионирование/резервные копии/лимиты адресов).
2. **D3-B2**: главный тест (оба носителя политики: гаскет + 0x45).
   Завелась → чек-лист ниже. Не завелась → это и есть ответ по подписи:
   отвержение неподписанного блоба ФАТАЛЬНО (не «skip»); откат, путь C.
   (Замечание А2: в t02 ветка ошибки верификатора — svc#0x63 + обычный
   возврат, верхний уровень результат игнорирует; поэтому ожидание —
   «заведётся с VCN либо заведётся без VCN», не-запуск маловероятен.)
3. **D3-A (контроль)**: ожидание false-negative (APCB-патч без носителей
   политики не действует). Если вдруг VCN жив — модель §7.5 неверна.
4. Откат на любом шаге: полный образ дампа из шага 0 + Verify + md5.
5. **Чек-лист успеха D3-B2** (`linux_check.sh` из пакета собирает всё сам):
   - `dmesg | grep -iE 'amdgpu|vcn'` — ip-block VCN в инициализации
     (на стоке отсутствует);
   - **MMIO-проба** (первичный критерий, НЕ зависит от драйвера): регистры
     видеоблока читаются живыми значениями (не FFFFFFFF/00000000);
   - `amdgpu_firmware_info` — загрузка `renoir_vcn.bin` (нужен кернел
     1.92+ с `amdgpu.bc250_vcn_mode=1` и файл прошивки; в сток-ОС этого
     нет — успех виден по MMIO/dmesg, полный драйверный уровень отдельно);
   - `vainfo` — декод H264/HEVC (только с правильным кернелом+fw).
6. **Интерпретация**:
   - D3-C не грузится → каталог/перенос валидируются строже (механика!),
     пересборка; НЕ делать выводов про подпись.
   - D3-B2 грузится + VCN жив → двухносителейая модель подтверждена
     (гаскет 0x24 + TOS 0x45, оба носителя патчены); PSP не проверяет
     подпись этих носителей жёстко (soft-fuse-семантика).
   - D3-B2 грузится + VCN мёртв (MMIO FF) → блобы отвергнуты по подписи
     (skip, не фатально — согласуется с веткой ошибки в t02); далее
     путь C.
   - D3-B2 не грузится → отвержение неподписанного ФАТАЛЬНО; откат; путь C.
   - D3-A: false-negative ожидаем; VCN жив = модель §7.5 неверна.
7. Риски: (а) PSP отвергает UNSIGNED-блобы по подписи → остальные
   подсистемы не страдают (каталог и записи не тронуты; в D3-B2
   неподписанных блоба ДВА — порог отвержения тот же, ветка ошибки
   не halt); (б) перенос на 0x9E0000/0x9E4000 не принят → D3-C это
   выявит безболезненно; (в) APCB-патч не принят → правка в 3 байтах,
   легко диагностируется по UART.
   НЕ тестировать без полного дампа-бэкапа и программатора под откат.

## 11. Приоритет A закрыт (А1-А6): носители, верификация, досягаемость

**А1. TOS_SECURITY_POLICY 0x45 = ВТОРОЙ НОСИТЕЛЬ ЗАМКОВ (прорыв).**
Формат = тот же табличный, что гаскет ($PS1-конверт 0x100 + 0x40-хедер
тела + группы {type,count,pairs}). Сток (robin, 0x6E0 @0x9CA400):
grp 0x210(13 пар): **{0x03E810,0}**; grp 0x211(0); grp 0x280(100):
**{0x03A2011C,0x87FF}**, VCN-банка НЕТ; grp 0x281(31). Донор-цезанн
несёт анлок и здесь: 0x03E810=**6**, 0x03A2011C=**0x107FF**,
0x03A20124=0x10FFF, + VCN-хвост 5 пар в grp 0x280 (те же 5 пар, что
в нашем UNSIGNED-гаскете). Порядок PSP-каталога: гаскет (idx7)
применяется РАНЬШЕ 0x45 (idx15) → last-writer-wins: **стоковый 0x45
перезатёр бы анлок из гаскета** → D3-B v1 имел этот пробел, D3-B2
патчит ОБА носителя. robin45 grp 0x280 == gasket grp 0x280 побайтово
(таблицы согласованы платформой). Модель «два замка» уточнена до
«двух носителей»: замки (E810-гейт, апертура DF 1C/124, VCN-банк)
продублированы в гаскете И 0x45.

**А2. t02 (PSP BL2): верификация подписи — НЕ halt.** t02 хв-дампа ==
robin3 побайтово (офсеты переносимы). ARM-векторная таблица + Thumb-2,
svc 0xF2 (82 сайта): обёртки {запрос 0x20Б, ver, service-id}.
Верификатор svc#6 @0xee5c; вызывающий fn@0x12544; **при провале RSA →
svc #0x63 (пометка блоба) → обычный возврат, НЕ halt**. Верхний вызов
(fn@0x11a04 @0x12434) игнорирует результат верификации и уходит в
парковочный цикл (svc#0x56 + loop). SMN-мостовой движок @0x405c:
indirect-окно 0x03200400 (0x10000 enable / индекс / 0x10001 команда).
=> отвержение неподписанного носителя НЕ должно валить загрузку.

**А2c. t28 DRIVER_ENTRIES** — не загрузчик гаскета (таблица адресов
PEI-FV + 1 вложенный драйвер @+0x19f00); копий гаскета/0x45 в ROM нет
(только канонические @0x982000/@0x9CA400) → резервных носителей нет.

**А3. Полная карта VCN-банка (56 пар, из UNSIGNED-тела).** Протокол:
{0x0900C234,0}=program → 3 базовые маски (0x0900C830-838) → requester
policy ({0x0900C910,0x497fff},{0x0900C914,0x7fff}) → **8 апертурных
грантов** (паттерн {0x307,0,0x36,lo,hi}: диапазоны 0x20108-0x20117,
0x20180-0x20183, 0x20300-0x206ff, 0x21078-0x2107f, 0x21800-0x218ff,
0x20eb0-0x20eb7, 0x1f844-0x1f84f, 0x1f860-0x1f863) → {0x0900CB80,0xff}
= лок → {0x0900C234,1}=commit; затем grp 0x280-хвост переоткрывает
program, обнуляет 914/930, снимает лок (0x...B80←0), re-commit.
Сток-гаскет программирует 47 ЧУЖИХ банков (0x9003234-0x9300234),
VCN-банка (0x0900C234) в стоке НЕТ. **Матрица досягаемости банка**:
x86/DXE — НЕТ (окно AmdFabricAriDxe 0xE0000000 = только DF-fabric);
SMU — ДА (Q3 0x98 smn_write32, field-proven VULN-1 PoC: 56 записей
приняты, readback OK); PSP/TOS — ДА (мост 0x0320xxxx). Flash-путь (D3)
записей не требует — PSP применяет таблицу сам.

**А4. Софтверный Setup-путь СНЯТ.** CbsSetupDxe: 0 констант 0x0900Cxxx
(реестр SMN-поков не содержит VCN-банка); Setup.PE32: единственный хит
0x0900CC00 @+0x12f56 = IFR-данные форм (значение вопроса, не адрес
записи); донор-цезанн: 0 раз. Ручки записи в банк из x86/Setup нет.

**А5. 0x13 DEBUG_UNLOCK = реальный $PS1-образ** (size 0x1E00, ver
29.1C.0.1, тело шифровано — entropy 6.90): механизм присутствует, но
протокол = одноразовый challenge+token против ключа AMD — не подделать.
**0x4F @0x9CAB00** (0x10200) — сырой блоб без $PS1-конверта, 57.5%
ненулевых, entropy 4.77 — окончательно не идентифицирован (кандидаты:
MP5/SEV/NVRAM-подобные данные; на цепочку анлока не влияет — низкий
приоритет).

**А6. HW_IP_CONFIG 0x20 = IPDS-таблица** (size 0x450): побайтово
совпадает с головой живого discovery_robin.bin (0x2800, magic «IPDS»
@+0x3C) → конфиг IP у платы актуален; VCN как отдельный замок в IPDS
не фигурирует. Полный декод формата IPDS — бэклог.

**Стратегические факты (tools/roadmap_facts.py):** (1) в PSP/BHD
каталогах НЕТ записей RTM/подписей (0x05/06/07/70/71/72) → **x86-часть
BIOS НЕ подписана** (комьюнити-мод меняет 1 005 160 байт в FVMAIN
0xAE0088-0xC21EEB в проде); (2) классических OROM в чипе ноль (AA55+PCIR
пусто) — «обновление OROM» = пересборка FVMAIN, field-proven; (3)
состав PSP-региона именован полностью: t01/t02/SMU×2/ABL0-4/FW_XHCI/
DEBUG_UNLOCK 0x13/ключи/0x4F(не идентифицирован)/HW_IP_CONFIG 0x20/
гаскет 0x24/TOS_SECURITY_POLICY 0x45.
