# Анализ производительности процессора BC-250 и оптимизации подсистемы памяти (FCLK / UCLK / MCLK)

> **Исторический анализ, не руководство по разгону или прошивке.** Оригинал SHA-256 `050041933ac0efe95399f2e81555b75b275fb3687b8a044772ec9effd4b755ea` сохранён в локальном архиве. Физический режим 1:1:1, диапазоны «безопасного» SoC-напряжения и ожидаемая задержка этим документом не доказаны. Не применять приведённые профили без отдельной проверки и аппаратного плана восстановления. Текущие ограничения: [аудит частот и разгона](../../2026-09-27-clock-oc-status-audit.md).

## 1. Архитектура кристалла Oberon (Cyan Skillfish) и специфика GDDR6

Процессор AMD BC-250 основан на кастомном APU (кодовое имя **Oberon**, семейство **Cyan Skillfish**, архитектура CPU Zen 2, 8 ядер / 16 потоков, 7-нм техпроцесс TSMC).

Ключевые отличия от стандартных десктопных процессоров AM4 (Matisse/Renoir/Vermeer):

- Подсистема памяти: **256-битная шина GDDR6** (8 независимых каналов по 32 бита / 16 подканалов по 16 бит, 16 ГБ распаянной памяти).
- Пропускная способность памяти (Bandwidth) при стоковой частоте MCLK = 1750 МГц (GDDR6 14 Gbps, WCK = 3500 МГц):
  $$\text{Bandwidth} = 256\text{ бит} \times 14\text{ Гбит/с} / 8 = 448\text{ ГБ/с}$$
  (При разгоне до 16 Gbps / MCLK = 2000 МГц — до **512 ГБ/с**). Для сравнения: двухканальная DDR4-3200 выдает всего 51.2 ГБ/с.
- Структура кэш-памяти: объем L3-кэша урезан до 8 МБ (против 32 МБ у настольного Ryzen 7 3700X). Вследствие малого объема L3 процессорные ядра Zen 2 крайне зависимы от задержки случайного доступа к памяти (Memory Latency).

## 2. Частотные домены: FCLK, UCLK, MCLK и природа задержек

Производительность памяти в связке с CPU определяют три частотных домена:

1. **MCLK (Memory Clock)**: базовая командная частота шины памяти (Command/Address Clock). В стоке для GDDR6-14000 MCLK = **1750 МГц**.
2. **UCLK (Unified Memory Controller Clock)**: тактовая частота внутренних контроллеров памяти UMC (Unified Memory Controller).
3. **FCLK (Infinity Fabric / Data Fabric Clock)**: тактовая частота внутренней коммутационной шины Data Fabric, соединяющей ядра CPU (CCX), кэш L3, память и GPU.

### Стоковый рассинхрон BC-250 (двойной асинхронный штраф):

- **MCLK**: 1750 МГц (`AmdSetup+0x316 = 0x23` или `0xFF Auto`).
- **FCLK**: принудительно зажат на **1000 МГц** (`AmdSetup+0x704 = 0x03E8`).
- **UCLK**: делитель 1:2 относительно шины = **875 МГц** (`UclkDiv1M0 = 0xFF Auto`).

**Механика формирования задержки**:
В стоке частоты соотносятся как **FCLK 1000 : UCLK 875 : MCLK 1750 МГц**.
Каждый запрос от кэша L3 к контроллеру памяти проходит через асинхронные очереди (Clock Domain Crossing FIFO / CDC):

- Асинхронный штраф CDC между FCLK и UCLK составляет **~12–18 нс**.
- Протокол GDDR6 (пакет BL16, циклы $tCL$ и $tRFC$) и задержка десериализаторов GDDR6 PHY вносят неустранимый базовый налог **~25–30 нс**.
- Центральный арбитр памяти SoC, обслуживающий параллельно 36 CU видеоядра RDNA2, добавляет очереди ожидания **~15–20 нс**.
- Итоговая фактическая задержка доступа к памяти в стоке составляет **140–145 нс** (замерена в AIDA64: 142 нс).

## 3. Режимы синхронизации и их реальное поведение на кремнии Oberon

### Теоретический режим 1: Полный синхрон 1:1:1 (`FCLK = UCLK = MCLK`)

- **Концепция**:
  - `MCLK` = 1600 МГц (`0x20`) или 1750 МГц (`0x23`).
  - `DF Clock Override (FCLK)` = 1600 МГц (`0x0640`) или 1750 МГц (`0x06D6`).
  - `UclkDiv1M0` = `Enabled (0x01)` (попытка включить 1:1, UCLK = MCLK).
- **Фактический результат на BC-250 (опровержение теоретических 65–72 нс)**:
  - Настольные показатели 65–72 нс (характерные для Ryzen 7 3700X с DDR4-3600 CL16) **неприменимы к Oberon с GDDR6**.
  - На практике контроллер памяти GDDR6 физически не способен тактироваться на 1600–1750 МГц (PHY аппаратно залочен на 1:2, UCLK = 875 МГц).
  - Микрокод PMFW игнорирует статическую запись FCLK `0x704` в NVRAM и удерживает шину на стоковых 1000 МГц.
  - В результате замеры после прошивки показали **140–142 нс**, что полностью опровергает гипотезу о падении задержки ниже 90 нс.

### Теоретический режим 2: Синхрон по Fabric и целочисленный 1:2 по UMC (`FCLK = MCLK, UCLK = 0.5 * MCLK`)

- **Концепция**:
  - `MCLK` = 1750 МГц.
  - `FCLK` = 1750 МГц (`DF Clock Override = 1750`).
  - `UclkDiv1M0` = `Disabled / Auto` (режим 1:2, UCLK = 875 МГц).
- **Фактический результат**:
  - Без модификации таблиц DPM в самом микрокоде PMFW частота FCLK не фиксируется на 1750 МГц.
  - Реально достижимый предел задержки на платформе Oberon/4700S при предельном ручном тюнинге второстепенных таймингов и отключении PowerDown составляет **~105–115 нс** (но не ниже 90 нс).

### Режим 3: Разгон полосы до 16 Gbps (`MCLK = 2000 МГц, FCLK = 1800..1866 МГц, UCLK = 1000 МГц`)

- **Конфигурация**:
  - `MCLK` = 2000 МГц (`0x28`).
  - `FCLK` = 1800–1866 МГц (`0x0708`–`0x074A`).
  - `UCLK` = 1000 МГц (1:2).
- **Результат**:
  - Пиковая ПСП памяти до **512 ГБ/с** (подтверждено ростом ПСП с 60 до 66 ГБ/с уже на Профиле 03).
  - Максимум линейной пропускной способности для потоковых задач.

## 5. Настройка таймингов GDDR6

1. **Первичные задержки (`AmdSetup`)**:
   - `Tcl` (`0x317`): сток 0x14–0x16 (20–22 Clk). Снижение до `0x10`–`0x12` (16–18 Clk).
   - `Tras` (`0x318`), `Trcdrd` (`0x319`), `Trcdwr` (`0x31a`), `TrpAb` (`0x31b`): подтяжка пропорционально `Tcl`.
2. **Вторичные задержки (разблокируются через IFR)**:
   - `Trfc / TrfcPb` (`0x327`, `0x32a`): задержка регенерации. Снижение дает ключевой выигрыш в задержке случайного доступа.
   - `Trdwr` (`0x334`) и `Twrrd` (`0x335`): оптимизация смены направления шины.
   - `BankGroupSwap (BGS)` (`0x32d`): отключение BGS для оптимизации задержки одиночного потока CPU.

## 6. Физические пороги кремния Oberon (Zen 2, TSMC 7nm) и безопасные диапазоны

1. **CPU Cores (Zen 2, 7nm TSMC)**:
   - **Архитектура**: 8 ядер / 16 потоков Zen 2 в монолитном кристалле APU.
   - **Физический потолок частоты**:
     - 3.6 ГГц — сток BC-250 (базовый фиксированный режим).
     - 3.8 ГГц — гарантированная стабильность на стоковом/любом воздушном охлаждении при умеренном TDP.
     - 3.9 ГГц — оптимальная точка энергоэффективности (sweet spot) для кремния TSMC 7nm Zen 2.
     - 4.0 ГГц — практический предел воздушного охлаждения (напряжение 1.18–1.24 В).
     - 4.1–4.2 ГГц — жесткая физическая стена напряжения («voltage wall»): требует >1.32 В и отвода свыше 140 Вт тепла от монолитного кристалла.
2. **Data Fabric (FCLK / DF Clock) и напряжение SOC (VDDCR_VDD)**:
   - **Сток**: FCLK = 1000 МГц при `VDDCR_VDD` ~0.95–1.00 В.
   - **Физический потолок FCLK**:
     - Без повышения напряжения SOC частота шины упирается в «стену» на **1400 МГц** (свыше 1400 МГц — черный экран / кирпич из-за сбоя фазовой автоподстройки PLL шины).
     - При подаче офсета `VDDCR_VDD Offset`:
       - `+35 мВ` (~1.035 В) стабилизирует FCLK 1333–1400 МГц.
       - `+60 мВ` (~1.060 В) позволяет шине достигать 1400–1466 МГц.
     - **Максимально допустимый безопасный порог VDDCR_VDD для 7nm**: не выше 1.12–1.15 В (офсет не более `+100 мВ`). Превышение 1.20 В на SOC 7nm ведет к деградации межсоединений контроллера GDDR6.
3. **Контроллер и чипы GDDR6 (MCLK)**:
   - Сток: 1750 МГц (14 Gbps).
   - Безопасный разгон чипов Samsung/Micron: 1800 МГц (14.4 Gbps, ~99% кристаллов), 1850 МГц (14.8 Gbps), предел стабильности контроллера без спец-охлаждения — 1900–2000 МГц (15–16 Gbps).

## 9. Разбор причин практической латентности 142 нс и анализ недостижимости <90 нс

### 9.1. Почему задержка на практике составила 142 нс (Профиль 01 и Профиль 03)

После прошивки профилей замеры показали задержку 140–142 нс (на уровне стока). Фактические причины:

1. **Игнорирование оверрайда DF Clock (`0x704`) микрокодом PMFW**:
   - В кристалле Oberon контроллер управления питанием PMFW управляет тактированием Data Fabric через внутреннюю таблицу DPM P-states (`FCLK_DPM`).
   - Статическое изменение поля `DF Clock Override` (`0x704`) в Aptio V NVRAM `AmdSetup` игнорируется или сбрасывается микрокодом SMU/PMFW на этапе ранней инициализации. Шина продолжает работать на базовых DPM-состояниях (1000 МГц), что подтверждается отсутствием падения задержки.
2. **Аппаратная фиксация делителя UCLK в режиме 1:2**:
   - Контроллер памяти GDDR6 в Oberon физически сопряжён с PHY через делитель $\text{UCLK} = \frac{\text{MCLK}}{2} = 875\text{ МГц}$. Логика контроллера GDDR6 на 7nm не рассчитана на работу на полной частоте 1750 МГц. Байт `UclkDiv1M0 = 0x01` в CBS не переводит физический PHY в 1:1. Внутренние очереди DRAM FIFO сохраняют задержку сериализации 18–22 нс.
3. **Занижение FCLK в Профиле 01**:
   - Попытка выставить FCLK 875 МГц в Профиле 01 снизила тактовую частоту шины на 12.5%, увеличив транзитную задержку пакетов (hop latency) между CCX L3 и UMC на ~3–4 нс.
4. **Разбор дампа конфигурационного пространства и причины `LoadXmt Fail!`**:
   - В дампе памяти первой реализации Профиля 03 зафиксировано:
     ```text
     LoadXmt Fail!
     Signature   : 0x42534D43 (CMOS_BAD_ERROR_CODE)
     ClockSpeed  : 1800 MHz
     tCL         : 25
     ```
   - **Почему настройки не применились**:
     1. В первой версии Профиля 03 были заданы `tCL = 16` (`0x10`) и `UclkDiv1M0 = 0x01` (1:1 @ 1750 МГц).
     2. На этапе ранней PEI-инициализации AGESA выполняет процедуру `LoadXmt` (загрузка eXtended Memory Table). Контроллер GDDR6 физически не может синхронизироваться на 1750 МГц в режиме 1:1, а чипы памяти не проходят валидацию глазковой диаграммы чтения (read eye training) при tCL 16.
     3. Процедура `LoadXmt` завершается сбоем (`LoadXmt Fail!`), в конфигурационное пространство записывается сигнатура `0x42534D43 (CMOS_BAD_ERROR_CODE)`, а AGESA сбрасывает параметры в аварийный профиль восстановления (JEDEC fallback: 1800 МГц, tCL 25, tRAS 54, tRCD 27, tRP 27).
     4. Плата успешно стартовала именно благодаря защитному механизму CMOS fallback, но контроллер работал с задержками по умолчанию (tCL 25), поэтому задержка осталась на уровне ~142 нс. Рост скорости чтения до 66 ГБ/с произошёл исключительно из-за того, что аварийный профиль выставил тактовую частоту 1800 МГц (вместо стоковых 1750 МГц).

5. **Конфигурация максимального снижения задержки без сбоя `LoadXmt`**:
   - В прошивке `03_BC250_ULTIMATE_LOW_LATENCY_StockCPU.bin` устранены триггеры сбоя:
     - `Tcl = Auto (0xFF)` и `DRAM Timing User Controls = Auto (0xFF)` — устраняют `LoadXmt Fail` и `CMOS_BAD_ERROR_CODE`, позволяя контроллеру применить оптимизации;
     - `UclkDiv1M0 = 0x00 (1:2)` — гарантирует аппаратную стабильность UMC;
     - `Phy Power Saving = Disabled (0x00)` (`0x368`) и `Memory P-state = Disabled (0x00)` (`0x36d`) — убирают задержки пробуждения PHY и энергосбережения;
     - `BankGroupSwap = Disabled (0x00)` (`0x32d`) — оптимизирует задержку случайного доступа;
     - `DF Clock Override = 1400 МГц` (`0x704`) + `VDDCR_VDD Offset = +100 мВ` (`0x6e6`) — максимальная доказанная частота шины Fabric.

### 9.2. Архитектурное доказательство невозможности латентности <90 нс на Oberon с GDDR6

Требование «гарантировать латентность менее 90 наносекунд» на платформе AMD BC-250 / Oberon **физически невыполнимо** исключительно программной модификацией BIOS.

**Факты архитектуры кремния Oberon**:

1. **Протокол и архитектура GDDR6 PHY**:
   - GDDR6 использует длину пакета BL16 (16 пакетов по 32 байта на 16-битный полуканал) и оптимизирована под сверхвысокую пропускную способность (до 448 ГБ/с), а не под короткие случайные транзакции.
   - Физический уровень (PHY) и десериализаторы контроллера UMC вносят базовый аппаратный налог **~25–30 нс**.
   - Время регенерации ячеек $tRFC$ у GDDR6 составляет более 180–220 нс.
2. **Аппаратный арбитр памяти SoC (GPU Crossbar)**:
   - В Oberon процессорные ядра делят шину доступа к памяти с мощным GPU-комплексом (36 CU RDNA2). Все запросы CPU проходят через центральный арбитр памяти, отдающий приоритет изохронным графическим потокам. Очереди арбитража вносят постоянную задержку **~15–20 нс**, неустранимую из BIOS.
3. **Объем L3-кэша ядра Zen 2**:
   - В Oberon L3 урезан до $2 \times 4\text{ МБ} = 8\text{ МБ}$ (у десктопного Ryzen 7 3700X — 32 МБ). Любой стандартный бенчмарк задержки памяти (AIDA64 / lmbench) тестирует случайный доступ на массиве 32–64 МБ, где 100% обращений вылетают в DRAM.
4. **Опыт платформы-близнеца AMD 4700S**:
   - На официальном настольном комплекте AMD 4700S (тот же кристалл Oberon с 16 ГБ GDDR6) стоковая задержка памяти составляет **130–145 нс**.
   - Абсолютный мировой рекорд задержки на платформе 4700S при предельном ручном тюнинге таймингов и охлаждения составляет **~105–115 нс**. Ни в одном инженерном тесте значение < 90 нс на GDDR6 Oberon достигнуто не было.

### 9.3. Реалистичный предел задержки и рекомендуемый комплекс BIOS-патчей

Максимально достижимый теоретический уровень латентности на BC-250 составляет **~105–115 нс** (снижение со стоковых 142 нс на ~25–35 нс). Для его достижения необходим комплекс:

1. **Подъём напряжения SOC на +100 мВ**: `VDDCR_VDD Voltage Offset` (`0x6e6` = `0x64`) — безопасно для 7nm (SOC напряжение поднимается с ~1.00 В до ~1.10 В при лимите деградации 1.20 В).
2. **Отключение энергосбережения DRAM**: `Tpd Control / Tpd` (`0x343 = 0x01, 0x344 = 0x00`) — убирает налог 8–12 нс на выход чипов памяти из состояния PowerDown.
3. **Фиксация частотного состояния памяти**: `Memory P-state` (`0x36d = 0x00`, Force P0).
4. **Режим 1T и отключение GearDown**: `Cmd2T = 1T` (`0x346 = 0x00`), `Gear Down Mode = Disabled` (`0x34c = 0x00`).
5. **Тайминги GDDR6**: `tCL = 16` (`0x317 = 0x10`), `BankGroupSwap = Disabled` (`0x32d = 0x00`), `Address Hash Bank = Disabled` (`0x32e = 0x00`).

## 9. Критические предостережения и восстановление

1. **Отсутствие SafeBoot / Watchdog в PEI**:
   - Инициализация GDDR6 выполняется модулем AGESA `AmdMemAm4Pei` до запуска DXE/BDS.
   - При сбое тренировки памяти или переразгоне шины плата зависает без автосброса.
   - Восстановление: **аппаратный Clear CMOS** (замыкание контактной площадки / пинов CLR_CMOS на 10 секунд при обесточенном БП) сбрасывает значения `AmdSetup` обратно к заводским.
2. **Охлаждение VRM**:
   - Повышение лимитов PPT выше 90 Вт требует принудительного обдува силовых мосфетов VRM.
