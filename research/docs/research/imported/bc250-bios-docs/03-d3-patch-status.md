# Патч-пакеты D3: состав и анализ риска

## Пакеты

- D3: гаскет A+B по адресу 0x9E0000, APCB-патч (i), репоинт записи каталога 0x24.
- D3-C: вариант D3 без 0x45-зеркала.
- D3-B2: D3 плюс зеркало TOS_SECURITY_POLICY по адресу 0x9E4000 со следующими изменениями обоих блобов:
  - {0x03E810, 0 → 6} в группе 0x210 — включение сегментов VCN;
  - {0x03A2011C, 0x87FF → 0x107FF} в группах (0x201, 0x280) — снятие ограничения DF-окна;
  - {0x03A20124, 0 → 0x10FFF} в группе 0x201;
  - appended VCN-хвост из пяти пар в группу 0x280 (100 → 105) — дословная копия хвоста донора;
  - запись каталога 0x45 репоинтится; fletcher32 каталога пересчитывается;
  - APCB DFG wildcard: два слова 0x001FFF00 → 0x007FFF00, контрольная сумма пересчитана.
- Сборщик: `tools/patch-build/d3b2_build.py`; верификатор: `tools/patch-build/d3b2_verify.py`.
- Порядок записей каталога: гаскет (индекс 7) раньше политики (индекс 15); при last-writer-wins зеркало 0x45 обязательно.

## Анализ риска по путям применения

- Путь секвенсера fn@0x20d8 → fn@0x2178 (значения всех групп применяются):
  - E810 получает 6; DF-окно получает 0x107FF в обеих группах; VCN-хвост применяется со значениями; патч действует полностью.
- Путь fn@0xfeac (значения зануляются для всех типов кроме 0x280/0x281/0x282/0x284):
  - E810 получает 0 — совпадает со стоком, изменения нет, вреда нет;
  - значение 0x03A20124 в группе 0x201 зануляется — совпадает со стоком (сток несёт 0), вреда нет;
  - копии в группе 0x280 применяются со значениями: DF-окно получает 0x107FF, VCN-хвост применяется;
  - патч деградирует до «VCN-хвост + DF-окно»; ядро действия сохраняется.
- Неизвестный порядок групп решает конкуренцию копий 0x03A2011C между группами 0x201 и 0x280 в пути fn@0xfeac: при применении 0x280 после 0x201 значение 0x107FF выживает, при обратном порядке зануляется.
- Вывод: оба пути безопасны для прошивки; безопасность следует из совпадения занулённых значений со стоковыми.

## Перед прошивкой

- Вердикт фазы C (`docs/08-verification-chain.md`): блобы 0x24/0x45 подписаны RSA-2048 (хвост 0x100 байт = подпись, kid 96EA из $KDB записи 0x50); верификацию выполняет PSP-загрузчик вне контейнера TOS.
- D3-B2 и D3-C с непереподписанными гаскет/политикой будут отвергнуты при загрузке; риск — деградация/кирпич на cold boot; НЕ прошивать до решения подписи.
- Каталожный fletcher32 и репоинт записей валидны; блокирует именно подпись блоба, а не каталог.
- APCB-часть D3 (DFG wildcard, checksum-only) подписью не защищена — безопасный компонент пакета.
- Зафиксировать md5 сток-образа на чипе.
- Снять MMIO-дамп VCN до прошивки.
- Порядок теста: сначала APCB-only вариант (без 0x24/0x45); D3-C/D3-B2 — только после обхода подписи (mailbox-инъекция или ключ).
