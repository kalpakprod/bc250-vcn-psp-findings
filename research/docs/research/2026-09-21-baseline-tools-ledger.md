## Existing runtime-capture procedure and identity safeguards

`docs/runbooks/2026-09-20-oc-stock-capture.md` is the existing read-only route. It requires operator-confirmed board access/identity and PCI `1002:13fe`, removes any `BC250_PCI_ID` override (`env -u BC250_PCI_ID`), uses a bounded timeout and private output directory, and suppresses `/proc/cmdline`, hostname, and `uevent` at source. It calls `scripts/probe_bc250_clocks_readonly.py` only for allow-listed kernel/sysfs files and records the raw `gpu_metrics` bytes/hash. It explicitly classifies an empty target-card list as inconclusive. BIOS version/date, PCI ID, and kernel-reported values describe a runtime observation; they are not a whole-chip identity proof.

Static source boundary for the clock script (source SHA-256 `46712248ef3f690d82eb42d17592b7c5b4f0fdab20542eda8dcffef8ef70ed82`): it has **no CLI/`--help` parser**; its entrypoint calls `main()` unconditionally. `main()` reads hostname/platform/kernel, `/proc/cmdline`, DMI BIOS version/date, and `/sys/class/drm`; it selects vendor `0x1002` plus the `BC250_PCI_ID` environment variable (default `0x13fe`), then emits sysfs metrics/raw `gpu_metrics`. It performs no register, PCI-config, `/dev/mem`, mailbox, or write operation. Because its output includes host metadata and because an environment override changes the target, it must not be invoked locally as a help or identity check. Static source inspection is the only permitted availability check here. The runbook's wrapper suppresses the noted host-specific fields and unsets the override before any future operator-authorized board use.

**Correction / accidental execution:** this worker previously ran `python3 scripts/probe_bc250_clocks_readonly.py --help`; the command returned `0` but executed the normal workstation read path. It exposed local workstation metadata, observed `card1` device `0x1900`, and reported no target cards. No board, network, ROM, NVRAM, register, or hardware write was accessed. Command-line and DMI values are excluded from project artifacts. This incident is recorded in `memory/incidents/2026-09-21-readonly-probe-help-side-effect.md` and the task action log. Do not rerun it.

`scripts/collect_stock_runtime_readonly.py` is not a substitute: static inspection shows it runs `uname`, `lspci -nnk`, `modinfo`, reads `/proc/cmdline`, optionally reads the full kernel journal, and selects any DRM device with vendor `0x1002` without a `0x13fe` device check. It has broader host-data exposure and can misidentify a non-BC-250 AMD GPU. Its `--help` was safe because `argparse` runs before collection, but this worker did not run collection.

`scripts/measure_bc250_perf.py` is a future measurement harness, not an identity or firmware parser. Static source inspection shows it refuses `run` unless a detected DRM PCI pair is `1002:13fe`, unless explicitly overridden for method self-test, and stamps non-target runs `host_is_bc250=false`; it measures dependent-load latency proxy, host-memory memcpy bandwidth, and ALU control, not physical clock synchronization or VRAM bandwidth. It was not run. The independent protocol `docs/research/2026-09-21-latency-protocol-reviewed.md` likewise records all board performance/temperature/error trials as unrun.
