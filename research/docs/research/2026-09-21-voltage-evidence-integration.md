## Decision snapshot

- Preserve the operator's memory baseline as the **IFR-labelled 1800 request**: in the pinned donor `AmdSetup+0x316 = 0x24`, whose exact HII option label is `1800MHz`. Do not change it in this integration. That byte is a stored request, not a measured physical clock.
- Treat **SoC 1.15 V as the user's target constraint only**. The checked BIOS fields, Linux source and public board annotation do not establish a BIOS control that sets the physical SoC rail to 1.15 V, nor that 1.15 V is a safe ceiling.
- There is **no evidence-backed recommended voltage, safe maximum, or latency improvement estimate**. UI maxima and historical profile values are not hardware limits. No equal requested/displayed numbers establish clock synchronization.
- The BIOS contains native HII fields and PEI consumer code for certain named voltage settings, but exact live menu visibility, PEI dispatch, external-controller semantics, physical rail mapping, and applied output remain unresolved.

## Proven versus not proven

**Direct local observations in this integration:** exact donor SHA-256 and raw field bytes; exact PEIM image slices and their SHA-256; assigned current report hashes; fixed-voltage decoder manifest (`11/11 OK`); and deterministic decoder output identical to the existing machine result (`exit 0`, stderr empty, SHA-256 `3da15d4a281cbbd3d5c05f97e3ea74cdaea547d6114503af1bbd29c55785fe3f`). The pinned Linux driver/core copies in `/tmp` match the source hashes recorded in the upstream-source reports; their callback/match/read-versus-set distinctions were inspected as source, not executed.

**Report/source claims retained with boundaries:** the Linux/PMBus reports cite the archived official PMBus specification for possible read/write coefficient differences and the board reports cite a pinned community hardware page/image. These were audited as reports and their local report hashes checked here; those external sources were not re-fetched by this integration. The latest callback-verification report is hash-checked and narrows the Linux claim to a source-level callback-contract discrepancy.

**Not demonstrated:** live Setup visibility or user saving; current board NVRAM; PCD/DEPEX dispatch; whether PEI controller writes execute; physical controller/page/net identity; actual voltage; a safe voltage ceiling; physical MCLK/UCLK/FCLK or synchrony; memory training; or latency/performance impact.
