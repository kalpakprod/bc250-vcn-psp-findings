== C2 runtime unlock channel - consolidated static findings ==

-- 1. Token install command ==
cmd 0x100B -> arm 0xC0C4 -> bl fn@0x3528 (b1_emul2 sweep, evidence/b1_emul2.txt).
arm 0xC0C4: r0=[sp+0x20] (session handle), r1/r2=ldrd [r5] = {buffer ptr, size}.
fn@0x3528(msg, buf, size):
  * requires size >= 0x140, else error 0xFFFF300F.
  * flag byte @0xE188C0: if 0 (first call this boot), derives the 0x20-byte token
    into 0xE25814 via fn@0x5fa0 (HMAC-like over key material @0xE17964/0xE179b2 and
    message data), sets flag=1. No svc calls in fn@0x3528 - derivation is local.
  * ALWAYS copies the current 0x20-byte token @0xE25814 to buf+0x100 (blx 0x14e4),
    writes 0x40 to buf+0x14. => the x86 side READS the per-boot token from the
    response buffer at +0x100. Token content is NOT attacker-chosen; it is revealed.

-- 2. Blob load: cmd 0x100C -> arm 0xC0D0 -> bl fn@0x13468 ==
arm 0xC0D0: r0 = [r5] = word0 of dispatcher message = pointer to descriptor
  {u32 src, u32 expect-ptr, u32 type}.
fn@0x13468(descriptor):
  * [r8]   = source (stream descriptor: 64-bit addr +0x10/+0x14, len +0x18),
    [r8+4] = expected 0x20-byte hash (WE supply it; fn@0xd1fc output compared to it),
    [r8+8] = blob type byte (stored to slot[0] later).
  * fn@0x6800 copies the blob from x86 memory via svc 0x8b/0x6b (supervisor DMA read).
  * received buffer header check: [buf]==0x9000 && [buf+4]==0x7F, else error 0xFFFF0005.
  * blob proper starts at buf+0x8000 (sb); header 0x100 bytes; body at sb+0x100.
  * memcmp#2 @0x1354a: body[0:0x40] must equal {token@0xE25814 || zeros} (0x40 bytes).
  * memcmp#1: fn@0xd1fc 0x20-byte output over the blob vs [r8+4] from the message.
  * RSA tail of the $PS1 blob: NOT verified on this path.
  * supervisor notification: svc 0x90 (alloc 0x1000, handle), svc 0x88(handle,1,1),
    copy 0x1000 bytes from sb (blob start) into the svc-0x88 buffer, then
    svc 0x68(0, 1, buf, 0x1000) = message to supervisor carrying the blob head,
    svc 0x63 free. => supervisor is the presumed registry (0xE5CBDC) filler.
  * success: slot registered in the 16-slot table @0xE4E538, slot format (8 bytes):
    [0]=type, [1]=runtime id (handle), [4]=pointer to received buffer;
    message descriptor [src+0x1C] = slot index + 0x10 (handle returned to x86).
  * fn@0x13468 does NOT write anything into 0xE5CBxx (only two literal refs to
    0xE5CBDC exist in the whole container, both 'ldr' - readers only).
  * cmd 0x100D -> fn@0x13680: unregister by handle (0x10..0x1F) - frees a slot.

-- 3. Registry read/apply ==
fn@0x1167c(type, &entry_ptr, &count): reads 0xE5CBDC DIRECTLY (no slot table):
  * entry count @0xE5CBDC+0x100;
  * entries start @0xE5CBDC+0x140, variable size:
    {u32 type, u32 pair_count, pair_count x {u32 addr, u32 val}}.
  * on match returns {addr of pairs area, pair_count}.
fn@0x2178 (per-group apply, called by sequencer fn@0x20d4 = cmd 0x1033):
  * type 0x203 / 0x217: direct RAM store *addr = val (no svc);
  * all other types (0x201, 0x205, 0x20A, 0x20B, 0x210): svc 0x7c(addr, val, 4)
    = secure register write, 4 bytes wide.
fn@0x20d4 sequencer order: 0x201 -> 0x205 -> 0x203 -> 0x20A -> 0x20B -> 0x210,
  then logs via fn@0x17124(0x5b, [0xE5CBDC+0x60]).
fn@0xfe04 (cmd 0xFFFF0001/0xFFFF0005, apply-all) iterates the SAME registry via
  fn@0x1167c @0xfebe.

-- 4. x86->PSP transport (recon, verified pieces from keshas_amdbc250_psp.c) ==
GPU BAR5 (NBIF MP0 C2P block, byte offsets):
  C2PMSG_35 @0x5818C = command; bit31 = completion (poll ~2s);
  C2PMSG_36 @0x58190 / C2PMSG_37 @0x58194 = argument / firmware physical address lo/hi;
  C2PMSG_64 @0x58200 = TOS-ready (bit31); C2PMSG_67 @0x5820C = ring WPTR;
  C2PMSG_69/70/71 @0x58214/18/1C = ring address lo/hi / size;
  C2PMSG_81 @0x58244 = SOS status (bit31 alive).
Blob handoff = physical address of a 4KB-aligned x86 DRAM buffer (page_to_phys via
/proc/self/pagemap); PSP DMA-reads it (fn@0x6800 svc 0x8b). No response payload
copyback beyond the polled registers / the shared buffer itself (token case: the
SAME buffer we passed is written at +0x100).
GFX mailbox command encoding (libgv_amdgv_psp_gfx_if.h): cmd = GFX_CMD_ID | fields;
LOAD_IP_FW = 0x06 | (FwType << 16), fw types: 13=VCN, 61=DFC, 67=REG_ACCESS_
WHITELIST, 0x4B=gasket (vendor gasket load time).
UNPROVEN: exact x86-visible encoding that posts a TOS dispatcher frame with cmd
word 0x100B/0x100C/0x1033 (dispatcher frames are 0x78 bytes, delivered by the
supervisor from the C2P stream/ring; only bootloader cmds 0x06/0x10000000 and
LOAD_IP_FW are documented from this board).
