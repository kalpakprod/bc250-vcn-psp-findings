# Приоритет A: результаты (А1-А6) — ЗАКРЫТ

База: дамп платы (md5 7607a34c…), robin3/5.00 hw-дампы, донор-цезанн.
Все разборы программные, верифицированы против 9 независимых ROM.

## А1. TOS_SECURITY_POLICY 0x45 — второй носитель замков (прорыв)

- Формат = тот же табличный, что гаскет: $PS1-конверт 0x100 + тело
  (0x40-хедер + группы {type u32, count u32, пары {addr,value}}).
- Сток robin (0x6E0 @0x9CA400): grp 0x210(13): {0x03E810,0};
  grp 0x211(0); grp 0x280(100): {0x03A2011C,0x87FF}, VCN-банка нет;
  grp 0x281(31).
- Донор-цезанн несёт анлок и в 0x45: 0x03E810=6, 0x03A2011C=0x107FF,
  0x03A20124=0x10FFF, + 5 VCN-пар в хвосте grp 0x280 (те же 5 пар,
  что в нашем UNSIGNED-гаскете: {C234,0},{C914,0},{C930,0},{CB80,0},
  {C234,1}).
- Порядок каталога: гаскет (idx7) применяется РАНЬШЕ 0x45 (idx15) →
  last-writer-wins: стоковый 0x45 перезатёр бы анлок из гаскета.
  **Следствие: D3-B v1 имел пробел; D3-B2 патчит оба носителя.**
- robin45 grp 0x280 == gasket grp 0x280 побайтово (таблицы согласованы).

## А2. t02 (PSP BL2): верификация подписи ≠ halt

- t02 hw-дампа == robin3 побайтово → офсеты прежних разборов в силе.
- ARM-векторная таблица + Thumb-2; svc 0xF2 (82 сайта, кластер
  0xee76-0x130c6); обёртки {запрос 0x20Б, ver, service-id};
  сервисы: #1 ×70, #2, #3, #6 = RSA-verify.
- Верификатор svc#6 @0xee5c; вызывающий fn@0x12544; при провале RSA →
  svc #0x63 (пометка блоба) → обычный возврат. Верхний вызов
  (fn@0x11a04 @0x12434) игнорирует результат и уходит в парковочный
  цикл (svc#0x56 + loop). **Отвержение неподписанного носителя не
  должно валить загрузку.**
- SMN-мостовой движок @0x405c: indirect-окно 0x03200400 (0x10000
  enable / индекс / 0x10001 команда).

## А2c. t28 DRIVER_ENTRIES — не при делах

Таблица адресов PEI-FV + 1 вложенный драйвер @+0x19f00. Копий гаскета/
0x45 в ROM нет (только канонические @0x982000/@0x9CA400) → резервных
носителей нет, патчить нужно ровно два блоба.

## А3. Карта VCN-банка (56 пар) и матрица досягаемости

Протокол банка (из UNSIGNED-тела):
1. {0x0900C234,0} = program-режим;
2. базовые маски 0x0900C830/834/838;
3. requester policy {0x0900C910,0x497fff}, {0x0900C914,0x7fff};
4. 8 апертурных грантов {0x307,0,0x36,lo,hi}: 0x20108-0x20117,
   0x20180-0x20183, 0x20300-0x206ff, 0x21078-0x2107f, 0x21800-0x218ff,
   0x20eb0-0x20eb7, 0x1f844-0x1f84f, 0x1f860-0x1f863;
5. {0x0900CB80,0xff} = лок; {0x0900C234,1} = commit;
6. grp 0x280-хвост: переоткрыть program, {C914,0},{C930,0},{CB80,0},
   re-commit — донорская последовательность снятия замков.

Сток-гаскет программирует 47 чужих банков (0x9003234-0x9300234),
VCN-банка (0x0900C234) в стоке НЕТ.

Досягаемость банка в рантайме:
- x86/DXE — НЕТ (окно 0xE0000000 = только DF-fabric);
- SMU — ДА (Q3 0x98 smn_write32; field-proven VULN-1 PoC);
- PSP/TOS — ДА (мост 0x0320xxxx);
- Flash-путь (D3) — записей не требует, PSP применяет таблицу сам.

## А4. Софтверный Setup-путь снят

CbsSetupDxe: 0 констант 0x0900Cxxx. Setup.PE32: единственный хит
0x0900CC00 @+0x12f56 = IFR-данные форм. Донор: 0 раз. Ручки записи
в банк из x86/Setup не существует.

## А5. DEBUG_UNLOCK 0x13 и 0x4F

- 0x13 = реальный $PS1-образ (size 0x1E00, ver 29.1C.0.1, тело
  шифровано, entropy 6.90): механизм присутствует, но протокол =
  одноразовый challenge+token против ключа AMD — не эксплуатируем.
- 0x4F @0x9CAB00 (0x10200) — сырой блоб без конверта, не
  идентифицирован (на цепочку анлока не влияет; бэклог).

## А6. HW_IP_CONFIG 0x20 = IPDS

Побайтово совпадает с головой живого discovery_robin.bin (0x2800,
magic «IPDS» @+0x3C). Конфиг IP актуален; VCN как отдельный замок в
IPDS не фигурирует. Полный декод IPDS — бэклог.

## Стратегические факты

1. В PSP/BHD каталогах НЕТ записей RTM/подписей → x86-часть BIOS не
   подписана (комьюнити-мод: 1 005 160 байт правок FVMAIN в проде).
2. Классических OROM в чипе ноль → «обновление OROM» = пересборка
   FVMAIN, field-proven.
3. Состав PSP-региона именован полностью (t01/t02/SMU×2/ABL0-4/
   FW_XHCI/DEBUG_UNLOCK/ключи/0x4F/HW_IP_CONFIG/гаскет/0x45).
