# VCN unclamp — план live-сессии (S1-S5 + A1)

Created 2026-09-25. Оператор: «проверь состояние платы, разрешаю начать, сам
формируй план и скиллы». AUTO mode.

## Цель (проверяемый исход)

Определить, прилипает ли рантайм-запись в DF/NBIF firewall-регистры (SMU Q3
0x98) так, что VCN выходит из master-abort окна. Критерий: `UVD_VERSION @
0x02403000+0x05C9` перестаёт читаться `0xFFFFFFFF`.

Два взаимоисключающих исхода, оба = валидный результат:
- owner/commit ВЕРНА → VCN распахивается рантайм (продолжить V3-V6).
- root-clamp → записи дропаются (LockDFReg) → вывод: путь только ROM-мод
  подписанного гаскета / glitch. Закрывает главную незакрытую ветку честно.

## Порядок исполнения (когда плата поднимется)

Полностью в скилле `vcn-unclamp-live`. Кратко:
0. board-liveness (свежий), enable_vcn.py --verify, msg 0x61 (поднять домен).
1. B → A по решению оператора. Рекомендация: B (S1 одиночная запись
   0x03A2011C 0x87FF→0x107FF — дёшево, быстрый сигнал) → при FF идти S2..S5.
2. Readback после КАЖДОЙ записи. Запись не прилипла → стоп (root-clamp).
3. UVD_VERSION != FF → успех, стоп записи, V3 (vainfo) / V5 (pm_info) / V6.

## Границы

- Flash НЕ трогаем. Все записи рантайм, обратимы cold power-cycle.
- PSP/APCB регионы не трогаем.
- Wedge → cold cycle, не тёплый reboot (SMU не сбросится).
