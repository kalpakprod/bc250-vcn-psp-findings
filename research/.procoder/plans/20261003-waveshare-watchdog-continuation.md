## 1. Цель и границы

Запрос03.10.2026: установить, где остановилась Waveshare, и дать конкретный план продолжения до подключаемого внешнего watchdog с записью напряжений и событий зависания BC250.

Результат следующего этапа реализации: Waveshare остаётся работающей при зависании/отключении BC250, сохраняет временной ряд доступных физических напряжений, потерю heartbeat, последние доступные Linux/UART данные и собственную причину перезапуска. Нельзя подменять этот результат Linux-метриками, которые прекращаются вместе с зависшей системой.

Один интегрированный образ сохраняет ранее запрошенные функции. Прежние ветки программатора, контроллера и диагностики не отменяются. Их незавершённость фиксируется отдельно, чтобы она не скрывала отсутствие регистратора. В данном запросе выполняется обследование и план, без прошивки, записи BIOS/SMU или физического подключения сигналов.

## 2. Точка остановки и источники

- PlaneBC250-60: исправление конкурирующих читателей CDC. Последний подтверждённый по журналу установленный образ5c1d; независимая проверка readback прошла. Поздний исправленный кандидат4986 собран, но запись его на устройство не зафиксирована.
- `docs/action-logs/20261001-waveshare-startup-repro-5c1d.md`: первоначальное «USB не запустился» отозвано. Устройство с Sony054c:0ce6 может быть Waveshare, поскольку оно эмулирует DualSense. USB интерфейсы появлялись; EACCES и отсутствие CDC ответа нельзя выдавать за отсутствие USB.
- Реальная найденная проблема исходника: Pico stdio USB и проектный dispatcher одновременно читали CDC RX. Текущий `CMakeLists.txt:488` задаёт `pico_enable_stdio_usb(unified 0)`, кеш ENABLE_SERIAL=ON, Waveshare profile=ON, USB_ONLY_DIAGNOSTIC=OFF. Это подтверждает исправление исходника, не работу на устройстве.
- `docs/action-logs/20261001-readback-waveshare-5c1d0677.md`: последний независимый readback/verify установленного образа. Дамп и исходные recovery файлы сохраняются.
- Текущая USB инвентаризация03.10: RP2350/эмулируемый Sony CDC на этом компьютере не обнаружены, `/dev/serial/by-id/` отсутствует. Это не устанавливает состояние отключённой Waveshare или подключённой к другому хосту платы.
- `src/adapter_metrics.c`: ровно5 принятых метрик: CPU/GPU температуры, GPU power, fan1/fan2; данные только linux_hwmon, свежесть5с. HOST_ALIVE после5с даёт unknown. Непрерывной физической записи напряжений и журнала freeze здесь нет.
- Поиск по текущим src и CMake не нашёл `watchdog_enable`, `watchdog_update`, `adc_init`, `adc_read`. Есть библиотека hardware_watchdog и сообщение watchdog_caused_reboot. Это не реализованный автономный watchdog/вольтметр.
- `scripts/waveshare_host_metrics.py` умеет читать существующие hwmon напряжения, но send_sample не передаёт напряжения в firmware; список firmware их не принимает.
- `docs/guides/waveshare-rp2350b-plus-w-general-wiring.md`: I2C_HEADER1 — PMIC/SMBus, не свободная сенсорная шина; подключение само по себе не даёт физические CPU/GPU напряжения.
- Для зависаний сегодня восстановлен отдельный netconsole: `docs/action-logs/2026-10-03-freeze-investigation.md`. Это дополнительное свидетельство, не замена внешним датчикам.

## 3. Существующие модули, которые используются

USB/CDC dispatcher, adapter_startup, adapter_metrics, adapter_network, UART RX/capture, существующий Linux helper, vendor board header, сохранённый BoardView и карта разъёмов. Не писать второй USB стек или отдельную несовместимую прошивку. Для питания/измерения использовать существующий совместимый измерительный модуль после проверки его конкретной схемы; модель пока не выбрана.

## 4. Сценарии и доказательства результата

| Сценарий | Что должно быть записано | Как принимается |
|---|---|---|
| Штатная работа | Последовательные timestamp/sample counter, физические V12 и другие доступные каналы, Linux значения с источником/возрастом | Сравнение измерительного канала с независимым эталоном, без передачи нулей вместо отсутствия |
| Heartbeat исчез, питание осталось | heartbeat_lost плюс продолжающиеся независимые аналоговые samples | Сначала остановка только отправителя heartbeat; запись не прекращается, событие не ошибочно называется доказанным kernel hang |
| Реальное зависание BC250 | Последние UART/Linux/netconsole записи, heartbeat_lost, напряжения до/после, продолжение Waveshare | Обычный следующий инцидент или отдельно разрешённый контролируемый тест; не провоцировать hang опасными SMN чтениями |
| Питание BC250 пропало | Напряжение падает, Waveshare продолжает запись | Разрешённое выключение именно BC250 при независимом питании регистратора |
| Сама Waveshare перезапустилась | Причина собственного reboot, разрыв sequence/time и ранее сохранённый incident | Проверка механизма своего watchdog без воздействия на BIOS/питание AMD |
| Home/геймпад | Нажатие доходит в Steam, меню появляется, ввод/звук сохранены | Обычное взаимодействие владельца после единого образа |

## 5. Порядок работы и контрольные результаты

### Шаг1: закрыть конкретный USB/CDC дефект

- [ ] Подключить Waveshare USB-C к этому компьютеру без проводов к AMD. Установить USB ancestry/интерфейсы и VERSION/STATUS, не определять устройство только по Sony VID.
- [ ] Проверить текущие байты/восстановление через имеющийся picotool. Выбрать конкретный исправленный образ из текущего исходника, а не верить имени FINAL. Согласовать точные новые байты по прежнему правилу прошивки.
- [ ] Проверить единственного RX владельца, ответ VERSION/STATUS после холодного старта и переподключения, затем controller+network. USB не должен исчезать при отсутствии геймпада.
- [ ] Откат — сохранённый рабочий образ/дамп Waveshare через BOOTSEL. Никакой записи BC250.

### Шаг2: схема реального измерения и независимого питания

- [ ] Начать с входных12В BC250 через съёмный измерительный переходник силового кабеля, без пайки/резки самой BC250. Подтвердить разъём/полярность по конкретному переходнику, выбрать измерительный модуль по диапазону/входной защите/полосе и схеме.
- [ ] Составить точную матрицу каналов: вход12В, доступная3.3V сеть, Vcore/GFX/SOC только при доказанной точке и подходящем подключении. Не обещать измерение внутренних шин через USB или один SMBus разъём.
- [ ] Waveshare питается отдельно от зависающей BC250. Обеспечить отсутствие обратного питания через USB/сигнальные линии; способ данных/развязки выбрать по готовой схеме, не соединять два источника5В напрямую.
- [ ] Выдать одну цветную схему: каждый кабель/контакт/направление/уровень, весь перечень оборудования. Неподтверждённую точку обозначить до подключения, не после ошибки. Покупки только после разрешения владельца.
- [ ] Эталонные измерения организует исполнитель; прежний отказ владельца от задания «сам измерь мультиметром» сохраняется. Без независимого эталона аппаратное измерение не принимать.

### Шаг3: реализовать регистратор в одном образе

- [ ] Использовать существующие CDC/network/metrics модули. Добавить физические каналы со своим источником, единицами, возрастом/валидностью, монотонным временем и sample sequence.
- [ ] Добавить события heartbeat_lost/recovered, power_drop, adapter_reboot; ядро и датчики не путать. Сохранить полезный интервал до/после события в ограниченном кольцевом буфере и выдать его в независимое долговременное хранилище. Выбрать объём/частоту после проверки RAM и полосы измерительного модуля; не писать flash на каждый sample.
- [ ] Собственный watchdog должен контролировать прогресс задач, а не просто вызываться в бесконечном цикле. Не давать USB/сети блокировать измерение и журналирование.
- [ ] Автоматическое отключение/перезапуск AMD по heartbeat не включать: это уничтожает исходный сбой и требует отдельного решения. Watchdog регистратора и watchdog AMD имеют разные задачи.
- [ ] Самые быстрые просадки питания не считать исключёнными медленным ADC: зафиксировать реальную частоту/полосу. При необходимости высокой временной точности нужен подходящий инструмент/модуль, а не программное обещание.

### Шаг4: подключение и единая аппаратная приёмка

- [ ] Один проверенный интегрированный образ; список конкретных исправлений и rollback рядом. Изолированные USB сборки только при конкретном необъяснённом дефекте, не как замена продукту.
- [ ] Проверить обычный поток, пропажу heartbeat без пропажи питания, независимую запись при разрешённом выключении BC250, восстановление после собственного reboot Waveshare.
- [ ] Проверить controller/Home/network и отсутствие потерь журнала при их работе. Обычная игровая сессия владельца, без самостоятельно запущенного stress test.
- [ ] Принять внешний регистратор только по выгруженному реальному incident и подтверждённым физическим измерениям. Софт-тесты/UF2 verify/имя FINAL этого не доказывают.

## 6. Открытые вопросы

Блокируют физическую приёмку: Waveshare отсутствует на текущем USB; фактический последний установленный образ требует перепроверки; измерительный модуль и независимое питание/сохранение не выбраны; подтверждённые точки и беспаечное крепление Vcore/GFX/SOC отсутствуют. Это конкретные оставшиеся работы, не просьба снова описать весь проект.

Не блокирует подготовку: временная метка может начинаться с монотонного времени и boot ID, пока нет синхронизации абсолютного времени; недоступные внутренние каналы явно помечаются. Их отсутствие не позволяет объявить полный набор напряжений готовым.
